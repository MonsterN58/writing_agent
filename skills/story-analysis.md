
# 故事分析：网文章节诊断

## 这个 skill 干什么

读已写好的章节，输出**结构化评估报告**：8 维度评级 + 优势清单 + 修改优先级。

**它只诊断不修订**——不写章节正文、不动设定、不改人设、不重写片段。评估完后把问题分流给具体的修订 skill。

## 何时不调

- 还没写到能评的程度（前 3 章都没成型 → 走 `drafting` / `outline-collaborator`）
- 结构层还有大问题（主线模糊、世界观漂 → 先走 `outline-collaborator` 做大纲层诊断）
- 作者要的是"哪里出问题"而非"评一下"（→ `outline-collaborator`）
- 作者要引导提问而非诊断结论（→ `story-coach`）
- 单段 / 单场景而非完整章节（→ `scene-sequencing`）

## 评估范围速查

| 模式 | 范围 | 重点维度 |
|------|------|---------|
| 单章评估 | 1 章 | 爽点、钩子、节奏、信息密度 |
| 多章连评 | 2-5 章 | 升级曲线、追读力、线索编织 |
| 卷级评估 | 一整卷 | 卷弧线、高潮质量、转折力度 |
| 黄金三章 | 前 3 章 | 开篇吸引力、设定交付、读者留存 |

## 8 评估维度

### 网文专项（NA）

| 维度 | 评估什么 | 危险信号 |
|------|---------|---------|
| **NA1 爽点密度** | 每章是否有爽的瞬间；铺垫-释放-反应是否完整；爽点类型是否多样（打脸/升级/获宝/逆转/社交胜利）；是否存在干旱期；**最近 5 章爽点密度是否在衰减**（趋势比单点更重要） | 连续 5 章无爽点；爽点类型单一；缺周围角色反应；密度曲线持续下行 |
| **NA2 升级节奏** | 主角是否有可感知成长；升级是否合理（太快没代入感、太慢读者跑）；新能力是否快速兑现展示；**配角是否同步成长**（避免主角变强后配角集体掉队）；**关键突破是否有仪式感**（境界跃迁/觉醒/顿悟需要重笔） | 连续 20+ 章无实力提升；每章都突破小境界（麻木）；只有数字变化没质变；配角永远停在初始水平；大突破被一句话带过 |
| **NA3 追读钩子** | 章末是否有钩子；类型是否多样（悬念/危机/期待/反转/情感）；章首是否兑现上一章悬念；付费节点前是否强力 | 钩子模板化（每章"就在此时"）；章首不兑现上章悬念 |
| **NA4 金手指平衡** | 金手指占问题解决比例；是否有"不能做"的限制；规则读者能否预测；**反事实提问：去掉金手指主角是否够用**（若全靠外挂，主角人设其实是空的） | 万能钥匙（任何困难都靠它解决）；规则随作者方便而变；抽掉金手指主角立刻变废 |

**爽点频率参考**：微爽点（每章 1-2 个）/ 小爽点（每 2-3 章）/ 中爽点（每 5-10 章）/ 大爽点（每卷 1-2 个）

**钩子类型**：悬念型 / 危机型 / 期待型 / 反转型 / 情感型

### 通用维度（SA）

| 维度 | 评估什么 | 网文特别关注 |
|------|---------|-------------|
| **SA1 叙事根基** | 核心冲突是否清晰；利害关系是否够；主线是否稳定推进 | 主线偏移 → 追读流失 |
| **SA2 角色表现** | 主角目标/个性；配角存在意义；反派动机；对话区分度 | 女性沦花瓶？反派只送人头？配角主角变强后被遗忘？ |
| **SA3 信息流** | 设定融入剧情而非倾泻；新信息节奏 | 修炼体系长篇说明；不通过角色互动传世界观 |
| **SA4 节奏密度** | 紧张/放松交替；是否水（内容少字数多）；场景长度匹配重要性 | 三章可压缩成一章 → 严重水 |

**节奏密度四分级参考**（给 ⭐ 评级一个锚）：
- **过密**：信息/转折堆到读者跟不上，关键情节没呼吸（⭐⭐ 以下）
- **适中**：紧张-松弛交替，重点场景有充分铺陈（⭐⭐⭐⭐ 以上）
- **略水**：可压缩 20-30%，但单章仍有实质推进（⭐⭐⭐）
- **严重水**：3 章可压成 1 章，整章无关键事件推进（⭐⭐ 以下）

## 黄金三章专项

前三章是网文生死线。专项 checklist：

**第一章**
- [ ] 前 500 字内建立核心冲突或悬念
- [ ] 主角有明确困境或目标
- [ ] 金手指/核心设定第一章内展示
- [ ] 章末有强力钩子

**第二章**
- [ ] 兑现第一章悬念（至少部分）
- [ ] 展示金手指核心能力
- [ ] 至少一个小爽点
- [ ] 建立更大期待

**第三章**
- [ ] 首个中等爽点（打脸/突破/逆转）
- [ ] 主角成长路径变得清晰
- [ ] 核心矛盾/对手浮出水面
- [ ] 读者有理由继续读第四章

## 诊断流程

1. **确认范围**：单章 / 多章 / 黄金三章 / 整卷？读对应章节文件。
2. **维度评估**：先 NA1-4（网文专项）后 SA1-4（通用）。
3. **生成报告**：用模板。优势和建议按影响力排序，每条修改建议指向交接 skill。

## 输出落点

| 范围 | 落点 |
|------|------|
| ≤3 章评估 | **对话里直接呈现**——信息密度低，写文件反而麻烦 |
| >3 章评估 | `write_file` 到 `/mnt/user-data/workspace/story-analysis-Ch{start}-{end}-{YYYYMMDD}.md`，**每次新文件，不追加**。评估是快照不是日志，作者只看最新；不同范围独立成文 |
| 跨次反复确诊的作品级模式 | 用 `work_memory` 写一条到 MEMORY.md `# 教训`/`# 约定` 段。**克制使用**——单次评估细节留对话/文件，只有"已 ≥2 次确诊同问题"或用户明确说"记下来"才值得写 |

**绝对不写**：
- `/mnt/user-data/chapters/` 任何文件——评估报告不塞回章节正文
- `/mnt/user-data/knowledge/` 任何文件——是 wiki-ingest 独占地盘，写入会双源打架

**`work_memory` 克制调用**：评估的同一回合**不要批量写**——单次评估细节留对话/文件，只有"已 ≥2 次确诊同问题"或用户明确说"记下来"才攒一条到 MEMORY.md（与上方落点表第 3 行口径一致）

## 大范围处理

| 章节数 | 推荐做法 |
|--------|---------|
| ≤ 10 章 | 主 agent 直接 read_file 完整评估 |
| 10–30 章 | 先读 `/mnt/user-data/knowledge/index.md` 取页面索引（log.md 是 wiki-ingest 的 append-only 流水账，不是摘要索引），挑代表性 5–8 章详读 + 其他章扫读关键段（章首/章末） |
| > 30 章 | 拆 `task` subagent，每 10 章一组，subagent 吐**评估摘要**而非完整报告，主 agent 汇总成总报告 |

## 下一步交接清单（写在报告末尾给作者）

## 反模式

**1. 清单暴政** — 把每个未达标项都标记需修复。**修正：** 按影响力排序，先问"这真的伤害了故事吗"。

**2. 类型盲区** — 用文学小说标准评网文（要求心理深度、诗意散文、反英雄）。**修正：** 先识别类型，评作品是否达成了它要成为的样子。

**3. 问题倾泻** — 一次列 50 个问题没优先级。**修正：** 找 3-5 个影响最大的，指出哪些做得好，给可操作的优先级建议。

**4. 忽视商业维度** — 只看叙事质量不看追读/留存/付费节点。**修正：** 网文是商业写作，追读和留存是评估体系一部分。

**5. 越界改写** — 评估完自己接着改章节。**修正：** 评估是评估，修订是修订。把建议交给具体 skill，不要自己跑去 prose-style / scene-sequencing 续力。

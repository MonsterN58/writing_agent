
# Pacing-Control：节奏控制

## 调用时机

- 用户说"这章节奏怪 / 太慢 / 太赶 / 注水了 / 没有起伏"
- 用户主动 `/pacing` 命令
- `chapter-planner` 设计单章纲时调用本 skill 判定本章拍位
- 写完 5 章 / 10 章后做阶段性节奏体检

> 本 skill 处理**节奏 = 信息密度 + 情绪曲线 + 章节分布**，比 `scene-sequencing`（管单章场景排序）更宏观，看跨章节奏。

---

## 节奏的三个维度

### 维度 1：单章内冷热段比例

**冷段**：信息铺垫 / 心理描写 / 设定介绍 / 环境描写
**热段**：冲突爆发 / 对话冲突 / 战斗 / 情绪高潮

**健康比例**：冷:热 = 3:7 或 4:6（热段占多数）

**异常**：
- 冷:热 = 7:3 → 注水 / 设定堆砌 / 节奏死
- 冷:热 = 9:1 → 几乎全是动作戏，读者疲劳
- 单段冷 ≥1000 字 → 必断节奏，插入对话或冲突
- 单段热 ≥1500 字 → 读者透支，插入短冷段缓冲

---

### 维度 2：跨章拍位分布

每章一个**主拍位**：

| 拍位 | 功能 |
|---|---|
| 爽 | 主角达成目标、打脸、装逼 |
| 憋 | 受阻、信息揭露但无力反击 |
| 打 | 实战冲突 |
| 升 | 修为/资源/关系/认知提升 |

**健康分布**（每 8 章范围）：

```
憋 → 打 → 爽 → 升 → 憋 → 打 → 爽 → 升
```

或允许小变化：

```
憋 → 憋 → 打 → 爽 → 升 → 憋 → 打 → 爽
```

**异常**：
- 连续 3 章+ 同拍位（连憋 / 连爽 / 连打）→ 节奏崩
- 升级章超过 25% → 流水账，缺乏冲突
- 爽章超过 40% → 爽点稀释，读者麻木
- 憋章超过 40% → 留存崩盘

---

### 维度 3：阶段性曲线

按弧光（约 20-30 章一弧）看曲线：

```
弧光开端（前 25%）：建立目标 + 第一次受阻
弧光中段（25-75%）：螺旋式推进 + 多次反转
弧光高潮（75-90%）：最大爆发 / 最大爽点
弧光收束（90-100%）：余韵 + 下一弧光铺垫
```

**异常**：
- 高潮太早（前 50% 就最大爆发）→ 后面写不动
- 高潮太晚（90% 后才到）→ 读者中途流失
- 全程平淡无高潮 → 弧光失败，必须重做

## 流程

### 第 1 步：定位用户问题

| 用户原话 | 落到哪个维度 |
|---|---|
| "这章读起来卡 / 拖" | 维度 1，冷热比例 |
| "感觉好几章都没大事" | 维度 2，跨章拍位 |
| "这一卷没高潮" | 维度 3，弧光曲线 |
| "不知道哪里怪" | 三个维度全扫 |

---

### 第 2 步：扫数据

#### 维度 1：单章扫

读章节正文，给每段标"冷"或"热"，统计字数比例：

```
段 1（200 字，热，对话冲突）
段 2（800 字，冷，环境+心理）  ← 单段冷过长
段 3（600 字，热，战斗）
段 4（400 字，热，对话）
段 5（300 字，冷，回忆）

总：冷 1100 / 热 1200，比例 48:52
单章评估：基本均衡，但段 2 单冷过长，建议拆成两段或插入对话。
```

#### 维度 2：跨章扫（最近 8 章）

读 `outline/chapters/chapter-N.md` 每章的 `拍位` 字段（chapter-planner 已记）：

```
第 1 章：升（开局）
第 2 章：憋
第 3 章：憋   ← 警告：连续 2 章憋
第 4 章：憋   ← 🔴 连续 3 章憋
第 5 章：打
第 6 章：爽
第 7 章：升
第 8 章：升   ← 警告：连续 2 章升

诊断：第 2-4 章过憋（应在第 3 章插入小爽 / 微打），第 7-8 章升级章太密。
```

#### 维度 3：弧光扫

读 `outline/arcs/arc-XX.md`：

- 弧光跨度多少章？
- 当前章在弧光的哪个位置（百分比）？
- 弧光高潮章是否已规划？

---

### 第 3 步：输出诊断 + 建议

写到 `reviews/critique/章N-节奏.md`：

```markdown
# 第 6 章 节奏扫描

## 维度 1：单章 ✅
冷热比 4:6，健康。无单段过长。

## 维度 2：跨章 🟡
最近 8 章拍位分布：升憋憋憋打爽升升

警告：
- 第 2-4 章连续 3 章憋 → 建议在第 3 章中段插入小爽点（如主角第一次成功使用某能力）
- 第 7-8 章双升 → 第 8 章应改为打 / 憋

## 维度 3：弧光 ✅
当前在第一弧光（30 章跨度）的 27%，符合"开端"节奏。
高潮章已规划在第 25 章（弧光的 83%），位置合理。

## 建议
1. 立即可做：第 8 章如未写，调整为打 / 憋
2. 中期可做：在第 3 章中段补 200 字小爽点（用 revision L2）
3. 长期可做：监控第 9-15 章避免再次连憋
```

---

### 第 4 步：交棒

诊断完成后：
- 用户接受改动 → 调 `revision` 改具体章节
- 用户接受调整后续节奏 → 调 `chapter-planner` 重做后续章纲
- 用户认可问题暂不改 → 写 `progress/todo.md` 备忘

本 skill **不直接改正文**。

## FAQ

**Q1：什么是"小爽点"？**
A：300-500 字的局部胜利。不解决主线冲突，但给读者短期满足（如：主角顶撞了配角、解决了一个小麻烦、领悟了一个细节）。

**Q2：如果用户故意写慢节奏文学向，怎么办？**
A：看 SOUL.md 基调字段。如果是"文学向 / 慢热向"，本 skill 阈值放宽（连憋 5 章才警告，冷热比放宽到 5:5）。

**Q3：弧光高潮位置 80% 还是 90%？**
A：网文一般 80-85%。给后面留 15-20% 的余韵 + 下弧光铺垫。

**Q4：连憋 3 章但读者评论说"够爽"，怎么办？**
A：本 skill 算的是"理论节奏"，用户和读者反馈是事实。**用户主权 > skill**。本 skill 标记后用户说没事就不再警告。

**Q5：和 `scene-sequencing` / `story-analysis` 区别？**
A：
- `scene-sequencing`：单章场景排序（顺序 / 因果）
- `story-analysis`：文学性分析（人物动机 / 主题 / 隐喻）
- 本 skill：节奏（冷热 / 拍位 / 曲线）—— 数据化、可量化

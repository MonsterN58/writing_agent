
# Revision：四档改稿

## 调用时机

- 用户点击章节预览页的"改写"按钮
- 用户说"这段改一下 / 这章重写 / 整个第 X 章重做 / 这一卷结构有问题"
- 用户主动 `/rewrite` 命令
- `continuity-guard` 报 🔴 后用户确认要改

> **本 skill 不从零写**（那是 `drafting` / `chinese-novelist`），本 skill 改**已有稿子**。

---

## 四档改稿

不同档位的影响范围、token 消耗、风险等级完全不同。**先选档，再改**。

| 档位 | 范围 | 改动幅度 | 风险 |
|---|---|---|---|
| **L1 润色** | 字句级 | 不改情节、不改人设 | 低 |
| **L2 段改** | 段落级 | 改某段写法 / 增删细节 | 中 |
| **L3 章改** | 整章级 | 改情节走向 / 重排场景 / 改钩子 | 高 |
| **L4 结构改** | 跨章级 | 改大纲 / 重写多章 | 极高，慎用 |

---

## 流程

### 第 1 步：识别档位

如果用户没明示档位，按下表猜：

| 用户原话 | 档位 |
|---|---|
| "这句别这么写 / 改个词 / 文笔润一下" | L1 |
| "这段不够紧凑 / 加点细节 / 这段对话改改" | L2 |
| "这章节奏不对 / 这章重写 / 钩子换一个 / 主角这章决定改一下" | L3 |
| "这一卷整个不对 / 第 5 到 10 章重做 / 大纲要调" | L4 |

**模糊时主动澄清**：
> "你想：① 只改这段写法 ② 改这段情节 ③ 整章重写 ④ 后面几章一起调？"

---

### 第 2 步：备份原稿

**任何档位改稿前，先备份**。后端工具 `revision_backup` 自动把原文件复制到：

```
chapters/versions/章N-revision-YYYY-MM-DD-HHMM.md
```

或对于 outline / SOUL：

```
outline/versions/章N-纲-revision-YYYY-MM-DD-HHMM.md
```

> 用户可在文件树右键"历史版本"看到所有备份，随时回滚。

---

### 第 3 步：按档位执行

#### L1 润色

**只动字句，不动情节**。不调 wiki，不调 continuity-guard（不会引入新矛盾）。

输入：用户指定的段落 + 润色方向（"更口语 / 更文气 / 更紧凑 / 更有画面感"）
输出：替换段落

例：
```
原："他心潮澎湃，激动得难以言喻，泪水夺眶而出。"
润："他想说什么，喉咙却堵着。眼眶一热，先低下了头。"
```

调 `humanizer` / `prose-style` 辅助是常态。

---

#### L2 段改

**改情节细节，但不改本段在章节里的位置和功能**。

流程：
1. 让用户**明确说**这段要改成什么（不要 LLM 猜）
2. 调 `wiki-query` 确认人物状态/设定
3. 重写本段（保持入口/出口和原段一致——前一段衔接、后一段承接不能断）
4. 写入正文，**自动重跑 continuity-guard**（限本章）

例：
> 用户："把第 3 场景'夜探王家'改成'白天硬闯王家'。"
> 操作：① wiki-query 王家戒备情况 ② 重写场景，把夜色描写改成白天硬闯 ③ 检查后续场景的入口（"翻进墙后"要改成"踹开门后"）④ 跑一致性扫描

---

#### L3 章改

**重写整章**。最常用、风险最大。

流程：
1. 读现有单章纲 `outline/chapters/chapter-N.md`
2. 询问用户：**改章纲还是只改正文？**
   - 改章纲 → 先调 `chapter-planner` 重做单章纲，再调 `chinese-novelist` 写新正文
   - 只改正文 → 在原章纲基础上让 `chinese-novelist` 重写
3. **保留**：章号、章名（除非用户改名）、与上下章的衔接（上章悬念怎么接、下章怎么继续）
4. **可改**：场景节拍、对话、钩子、字数
5. 写完跑 `wiki-ingest`（更新本章实体变动）+ `continuity-guard`

> **重写后 wiki 可能漂移**——例如原章里林尘吃了某丹药突破，新章删了这段，但 wiki 已记录突破。本 skill 必须**调 `wiki-ingest --rebuild N`** 重抽本章。

---

#### L4 结构改（极慎）

**跨多章 / 改大纲 / 改 SOUL**。

流程：
1. **强制澄清**用户范围："改第几到第几章？要不要改总纲？要不要改 SOUL？"
2. **强制让用户确认**："这会重写约 N 章 / 约 X 万字，确认开工？"
3. 按"先改大纲再重写章节"顺序：
   - 调 `outline-collaborator` 改总纲 / 弧光
   - 调 `chapter-planner` 逐章重做单章纲
   - 调 `chinese-novelist` 逐章重写正文
4. **批量 wiki 重建**：`wiki-rebuild --from N --to M`
5. **全局一致性扫描**：`continuity-guard --full`

> L4 是核武器。**不要轻易触发**。如果用户只是觉得"前面铺垫不够"，往往 L3 单章重写就够。

---

### 第 4 步：交付 + 摘要

每次改稿完成，输出一段简短摘要：

> "L2 段改完成：第 6 章场景 3 改为白天硬闯。备份在 versions/章6-revision-2026-05-04-2150.md，一致性扫描 0 致命。"

并把改动写入 `memory/decisions.md`：

```markdown
## 2026-05-04 21:50 第 6 章 L2 段改
- 场景 3：夜探 → 白天硬闯
- 原因：用户认为夜探不符合主角刚立功后的心态
- 备份：versions/章6-revision-2026-05-04-2150.md
```

## FAQ

**Q1：用户说"这章不行重写一下"——L3 还是 L4？**
A：默认 L3（单章重写）。如果用户原话提到"前面几章 / 大纲 / 整体"才升 L4。

**Q2：L1 润色会不会改坏作者声音？**
A：调 `prose-style`（确认作者文风）和 `humanizer`（去 AI 味），但**禁止改情节信息密度**——只换措辞，不增删事件。

**Q3：改完 wiki 没自动更新怎么办？**
A：本 skill 强制在改完后调 `wiki_ingest --rebuild N`。如果用户跳过这一步，下次扫描会报漂移。

**Q4：改稿次数没上限吗？历史版本会不会爆？**
A：每次改都备份，历史版本只占文本空间，可控。但 UI 上对超过 10 个版本的章节会折叠成"展开 N 个旧版本"。

**Q5：L4 改完后续怎么办？**
A：L4 改完后，本 skill 强制弹出"待办清单"到 `progress/todo.md`：
- [ ] 检查改动后的章节字数总览
- [ ] 检查 SOUL.md 红线是否仍然成立
- [ ] 跑全局 foreshadow-tracker
- [ ] 用户审阅前 3 章重写效果

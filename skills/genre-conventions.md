
# 类型惯例：诊断与生成技能

你诊断网文类型层面的故事问题并生成类型特定的元素。你的角色是确保故事兑现对读者的核心爽点承诺。

## 核心原则

**类型是对读者的爽点承诺。故事必须在前三章兑现这个承诺，否则读者会直接弃书。**

网文类型关乎核心爽点与阅读快感，而非简单的题材标签。一个发生在都市背景的故事可以是系统文，也可以是重生文。设定不等于类型，读者追更的驱动力才是类型。

## 十一大网文类型

> **类型 key 与脚本对齐**：本表的中文名后括号中是 `genre_elements.py / genre_blend.py / genre_check.py` 的英文 key。调用脚本时使用英文 key（如 `--genre game`）。

| 网文类型 | 核心承诺 | 读者期待 |
|---------|---------|---------|
| **玄幻** (`xuanhuan`) | 修炼突破的爽感 | 打怪升级、境界突破、逆天改命 |
| **都市** (`urban`) | 现代都市的逆袭传奇 | 装逼打脸、商战权谋、马甲身份 |
| **仙侠** (`xianxia`) | 求仙问道的旅程 | 仙门争斗、天劫渡劫、道心磨砺 |
| **科幻** (`scifi`) | 未来科技的想象 | 星际探索、文明碰撞、技术奇观 |
| **末世** (`apocalypse`) | 绝境求生的紧迫 | 丧尸变异、资源争夺、人性考验 |
| **游戏 / 系统文** (`game`) | 系统金手指的碾压优越感 | 系统任务、属性面板、副本掉落 |
| **历史 / 军事** (`historical`) | 历史风云的沉浸 | 朝堂博弈、运筹帷幄、家国情怀 |
| **言情** (`romance`) | 情感关系的满足 | 甜宠虐恋、双向奔赴、破镜重圆 |
| **悬疑 / 灵异** (`suspense`) | 真相揭露的快感 | 诡异事件、层层揭秘、反转高能 |
| **奇幻** (`fantasy`) | 异世界的冒险 | 魔法体系、转生勇者、组队探险 |
| **武侠** (`wuxia`) | 江湖恩怨的快意 | 门派纷争、侠义恩仇、绝世武学 |

**注意 1：** 古代、现代、未来是*时代背景*，不是类型。一个古代背景的故事可以是仙侠、言情或历史。背景是类型生长的土壤，爽点才是类型本身。

**注意 2：** **穿越重生**、**无限流** 不作为独立主类型——按"穿越/无限流 + 主类型"的副类型混搭模式诊断（如"穿越+古代+言情"=穿越古言；"无限流+悬疑"=无限恐怖流），由 `genre_blend.py` 处理混搭策略。

## 类型状态

### 状态 G1：缺失类型承诺

**症状：** 故事前三章没有明确的爽点信号。读者读不出这是什么类型的书，不知道追更能获得什么体验。开头既像玄幻又像都市，什么都沾一点但什么都不深入。

**网文场景：** 前三章既有修炼体系描写又有校园日常，还穿插了系统面板，读者评论"这书到底写的是啥？"

**关键问题：**
- 读者追更的核心驱动力是什么？（升级？打脸？甜宠？求生？）
- 前三章是否清晰传达了核心爽点？
- 书名和简介承诺的体验与正文是否一致？
- 如果读者在书评区用一个标签概括你的书，那个标签是什么？

**干预措施：**
- 明确一个核心爽点作为主类型
- 在第一章前500字内植入类型信号（如修炼体系→玄幻，系统面板→系统文）
- 检查书名、简介、标签是否与正文类型匹配

---

### 状态 G2：类型错位

**症状：** 故事标签与实际内容不匹配。标签挂的是一种类型，实际写的是另一种类型。读者因为标签进来，因为内容不符预期而离开。

**网文场景：** 标签是"热血玄幻"但前十章全是感情戏，追更的读者想看打斗升级却一直等不到；或者标题写"重生之商业帝国"结果主角一直在谈恋爱。

**关键问题：**
- 你实际在写的爽点是什么？
- 哪个类型最能承载你的核心素材？
- 读者进来期待什么，你实际给的是什么，两者之间差距多大？
- 如果换一个类型标签，故事是否会更顺畅？

**干预措施：**
- 将类型标签对齐到实际内容，而非把内容硬塞进错误的标签
- 如果真正想写的是感情戏，就从"热血玄幻"改标为"玄幻言情"
- 重新调整简介和前三章以传达真实类型信号

---

### 状态 G3：类型混搭冲突

**症状：** 两套或多套类型体系在同一本书中相互矛盾。不是简单的融合不够好，而是底层逻辑打架。读者觉得设定混乱、体系崩了。

**网文场景：** 系统文+修仙混搭，但系统的数值化升级逻辑与修仙的悟道渐修逻辑相互矛盾——主角一边靠刷任务升级，一边又要闭关悟道，读者困惑到底哪套规则算数。

**关键问题：**
- 两套类型体系的底层逻辑是否兼容？
- 当两套规则冲突时，哪套优先？
- 能否找到一个统一的解释框架让两者自洽？
- 读者是否需要同时理解两套体系才能看懂故事？

**干预措施：**
- 确立一个主类型作为底层逻辑，另一个作为表层风味
- 找到两套体系的嫁接点（如：系统是辅助悟道的工具，而非替代品）
- 在前期就明确规则，不要让读者自己猜

---

### 状态 G4：副类型喧宾夺主

**症状：** 支线的类型元素不断抢占主线篇幅。本该是配菜的类型变成了主菜，而读者是冲着原本的主菜来的。

**网文场景：** 一本玄幻修仙文，后宫感情戏越写越多，到了中期几乎变成了言情小说。追更的男频读者大量流失，评论区全是"能不能少写点感情多写修炼"。

**关键问题：**
- 主要的爽点驱动力是什么？
- 副类型元素占了多少篇幅？超过30%就需要警惕
- 副类型是在强化主类型体验还是在打断它？
- 目标读者群体的核心诉求是什么？

**干预措施：**
- 建立清晰的类型主次关系，主类型占至少60%篇幅
- 将副类型限制在特定章节或支线中，不要让它侵入主线高潮
- 用副类型来增强主类型的利害关系（如：感情线让修仙之战的赌注更大）
- 如果副类型持续膨胀，考虑分书或转型

---

### 状态 G5：缺少类型必备元素

**症状：** 挂了类型标签但缺少该类型读者默认期待的核心要素。不是写得不好，而是根本没有。读者觉得"货不对板"。

**网文场景：** 标签是"系统文"但只在开头出现了一次系统面板，之后再也没有系统交互；或者写"末世文"但没有生存压力，主角过得比现实还舒服。

**关键问题：**
- 这个类型读者最核心的期待元素是什么？
- 当前草稿是否包含了这些元素？
- 缺失的元素能否自然融入现有故事？
- 是否在用其他元素替代但效果不佳？

**干预措施：**
- 对照类型必备清单逐项检查
- 使用 genre-elements 工具生成缺失元素的具体方案
- 确保核心元素在前十章内全部亮相

---

### 状态 G6：类型套路僵化

**症状：** 所有类型元素都在，但全是读者看过一千遍的老套路。没有任何新意或个人特色。评论区的反应是"粮草""还行""不功不过"而不是"真香""追更停不下来"。

**网文场景：** 玄幻文写的是"废材觉醒→退婚打脸→踩小人→升级→换地图→继续踩"的标准流水线；重生文写的是"重生→炒股买房→打脸前妻→商业帝国"的模板剧情。没有跳出模板的东西。

**关键问题：**
- 你在默认使用哪些类型套路？
- 哪些可以保留（读者真正喜欢的爽点），哪些可以翻新？
- 有没有可能用反预期的方式兑现同样的爽点？
- 你的故事相比同类型热门书的差异化卖点是什么？

**干预措施：**
- 交接给 cliche-transcendence 技能进行创新分析
- 保留核心爽点但翻新实现路径
- 在关键节点制造反预期但合理的转折
- 从其他类型借鉴元素作为差异化手段

## 类型必备速查表

| 网文类型 | 体系/设定需求 | 角色需求 | 情节需求 |
|---------|-------------|---------|---------|
| **玄幻** (`xuanhuan`) | 完整修炼等级体系、功法/神通 | 有成长潜力的主角（低开高走）、对手递进 | 升级节点明确、战斗渐次升级、地图不断扩大 |
| **都市** (`urban`) | 当代社会背景、金手指来源合理化 | 低开高走的主角、各路看不起主角的配角 | 装逼打脸循环、身份逐步揭示、逆袭节奏明快 |
| **仙侠** (`xianxia`) | 仙道体系、天劫/飞升规则、宗门架构 | 有道心的主角、亦师亦友的配角 | 入门修行→宗门争斗→渡劫飞升、情与道的抉择 |
| **科幻** (`scifi`) | 科技设定自洽、技术体系有逻辑 | 有专业素养的主角、代表不同立场的阵营 | 技术驱动情节、文明冲突、想象力爆点 |
| **末世** (`apocalypse`) | 灾变规则、生存资源体系、威胁等级 | 有求生意志的主角、可信赖/可背叛的伙伴 | 生存压力持续、安全→危机循环、人性抉择 |
| **游戏 / 系统文** (`game`) | 系统面板、任务体系、奖惩规则、成长数值 | 善于利用系统的主角、不知情的配角 | 任务驱动情节、系统升级节点、金手指逐步展开 |
| **历史 / 军事** (`historical`) | 历史背景考据、权力结构、军事体系 | 有格局的主角、历史真实人物的合理演绎 | 战略博弈、势力消长、家国个人命运交织 |
| **言情** (`romance`) | 社会背景/身份障碍、情感发展空间 | CP双方人设鲜明有记忆点、合理的情敌/阻力 | 相识→误解/阻碍→心动→考验→HE/BE、糖虐节奏 |
| **悬疑 / 灵异** (`suspense`) | 诡异规则、信息层次、真相分层 | 有调查能力的主角、可疑的相关人物 | 悬念设置→线索铺设→阶段揭示→高能反转 |
| **奇幻** (`fantasy`) | 魔法元素体系、职业转职、种族多样 | 转生/失忆的勇者、性格鲜明的队友 | 异世界冒险、组队探险、击败魔王 |
| **武侠** (`wuxia`) | 内功心法体系、门派恩怨、兵器谱 | 亦正亦邪的剑客、心狠手辣的反派 | 江湖纷争、侠义恩仇、归隐前最后一战 |

## STEP 0：开写前的文件状态检查（硬闸，不可跳）

**任何持久化产出之前，先做下面这一步。** 没做 = 高概率覆盖前文。

```bash
ls /mnt/user-data/knowledge/genre-audit.md 2>/dev/null
```

根据结果选模式：

| 结果 | 模式 | 工具 | 行为契约 |
|------|------|------|---------|
| 文件不存在 | **首次创建** | `write_file` | 覆盖写入完整 4 核心节 |
| 文件存在 | **追加** | `str_replace` | 找对应节锚点，在节末插 `### YYYY-MM-DD 追加：<主题>` + 新内容 |

**追加模式的硬性约束**（违反任何一条 = 算 skill 失效）：

1. ❌ **禁止重写整文**——即使你觉得新版本更整洁、结构更优、可以"先重组再追加"。形式覆盖 = 信息覆盖，A 的"建议干预措施 ABC 三选项"就是被这种"我重组得更漂亮"思路砍掉的真实案例
2. ❌ **禁止用 `write_file`**——`str_replace` 是唯一合规工具，它天然不支持全文重写，强制你进入"局部插入"思维
3. ❌ **禁止改原 4 核心节锚点**（`## 一、类型诊断` / `## 二、必备清单` / `## 三、承诺分析` / `## 四、混搭结构笔记`）——下游 skill 和后续会话依赖这 4 个固定锚点定位
4. ✅ **允许**在节末插 `### YYYY-MM-DD 追加：<主题>` 三级标题 + 内容
5. ✅ **允许**新增"扩展节"（诊断状态详解 / 干预措施 / 风险预警 / 节奏建议 / 最终结论），但同样只能 append，不能改已有内容

**正确示例**（追加仙侠+悬疑混搭策略）：
```
str_replace(
  file_path="/mnt/user-data/knowledge/genre-audit.md",
  old_string="## 五、行动建议",  # 找到下一节的锚点
  new_string="### 2026-04-26 追加：仙侠+悬疑混搭策略\n\n[新内容...]\n\n---\n\n## 五、行动建议"
)
```

**反面示例**（C 轮真实翻车）：
```
write_file(
  file_path="/mnt/user-data/knowledge/genre-audit.md",
  content="# 《寒》类型审计报告\n## 一、类型定位修正\n..."  # ❌ 整份重写
)
# 结果：A 的 8 节 → 6 节，3 个节被砍，时间线丢失
```

## 诊断流程

当作者带着类型相关问题来找你时：

> **前置：先读 SOUL.md 题材字段，再决定要不要追问。**
> 作品宪章 SOUL.md 已由 lead_agent 的 prompt template 注入到当前 system prompt（参考 `<work_instructions>` 块的"题材"字段），**不要再 `read_file /mnt/user-data/SOUL.md`**——重复加载只是浪费 token。
> 如果题材字段已写明（例如"玄幻+系统"），直接进入步骤 2 对照诊断；只有当题材字段缺失或与正文明显冲突时才追问作者。
>
> **追问规范：用自然对话，不要连环调 `ask_clarification`。** lead_agent 的 `<clarification_system>` block 明确要求 multi-step skill 内用自然对话逐步收集信息，不要 repeatedly call ask_clarification。

### 1. 识别核心爽点

问："你的读者追更最大的驱动力是什么？"不是"你写的是什么分类？"而是"读者追更时期待的那个'爽'是什么？"

### 2. 检查前三章信号

前三章是否清晰传达了类型信号？第一章前500字应该包含至少一个核心爽点的明确标记。网文读者的耐心极其有限，三章定生死。

### 3. 审计必备元素

使用必备表。每个核心元素是否存在？出现频率是否足够？是否在关键节点（如每个小高潮）都有体现？

### 4. 检查副类型关系

如果有副类型混搭，它们之间的底层逻辑是否兼容？主次比例是否合理？副类型是在强化还是在削弱主类型体验？

### 5. 检查标签/内容一致性

书名、简介、标签承诺的是什么类型？正文实际兑现的是什么类型？两者是否一致？不一致会直接导致读者流失。

### 6. 推荐干预措施

基于识别出的状态，提供具体可执行的干预措施。必要时生成元素。指向相关框架。

## 反模式

### 无主次的类型缝合

**问题：** 故事试图同时当玄幻、系统文和言情，每种各占三分之一。读者不知道该期待什么爽点。这不是"融合创新"，这是"什么都写什么都不精"。

**修正：** 确立一个绝对主类型（60%以上篇幅）。其他类型作为调味料服务主类型。例如：主类型玄幻（修炼升级），副类型系统（辅助升级），点缀言情（增加赌注）。

### 以设定代替类型

**问题：** 被问到"你的书是什么类型"时回答"修仙世界"。花了大量篇幅写世界观和体系设定，但没有明确的爽点驱动。设定很宏大，但故事没有"勾"。

**修正：** 设定是骨架，类型爽点才是血肉。"这是一个修仙世界的复仇故事"有类型驱动力。"这是一个修仙世界"没有。

### 前后类型偷换

**问题：** 以热血战斗开场，中期变成宫斗权谋，后期变成种田文。每次类型转变都会流失一批读者。

**修正：** 在开书前就确定核心类型并贯穿始终。如果确实要融合多种元素，在前三章就展示全部类型基因，让读者自己判断是否继续追。不要承诺了升级打斗却给了种田日常。

### 有元素无节奏

**问题：** 修炼体系有了（玄幻），系统面板有了（系统文），感情线有了（言情），但全部平铺直叙没有高低起伏。元素存在但不产生爽感。

**修正：** 类型元素必须与节奏配合。升级要有铺垫→突破→碾压的节奏；打脸要有被轻视→积蓄→一击逆转的弧线。有元素无节奏等于没有。

### 反套路上瘾

**问题：** 每个类型期待都被刻意颠覆。本该升级的时候掉级，本该打脸的时候被打脸，本该发糖的时候虐心。读者完全找不到爽点。

**修正：** 核心爽点必须兑现。可以创新兑现的路径和方式，但不能取消承诺本身。读者应该通过意想不到的方式获得预期中的满足感，而不是什么满足感都得不到。

## 可用工具

### genre_elements.py

各类型的随机元素生成器。

> **路径提示**: 脚本位于 `skills/public/writing-craft/genre-conventions/scripts/` 目录下。
> 执行时必须使用从项目根目录出发的完整相对路径。

```bash
# 从指定类型随机生成元素
python skills/public/writing-craft/genre-conventions/scripts/genre_elements.py xuanhuan

# 生成特定子类元素
python skills/public/writing-craft/genre-conventions/scripts/genre_elements.py game --category system_elements
```

## 何时交接

- **转交 character-arc：** 当类型问题源于主角人设与类型需求不匹配（如玄幻文主角缺乏成长动力）
- **转交 scene-sequencing：** 当类型节奏问题实际上是场景层面的结构问题（如升级节奏拖沓）
- **转交 cliche-transcendence：** 当类型元素全是老套路时（状态 G6）
- **设定体系问题（如修炼体系不支撑升级爽感）：** 不另开 skill，让 `chinese-novelist` 写章时按其 system prompt `<skill_inline_references>` 块里预加载的 worldview-check W1-W4 自查（不需要 `read_file`）；作品级缺漏让用户回 `work-setup` 补 SOUL.md 世界观字段

## 交互示例

### 示例 1：缺失类型承诺

**作者：** "我写了五万字了，但读者一直在问这到底是什么类型的书，收藏涨不上去。"

**你的方法：**
1. 识别可能的状态：G1（缺失类型承诺）
2. 问："读者追你的书，最大的爽点驱动力应该是什么？升级？打脸？甜宠？解谜？"
3. 一旦作者识别了核心爽点，帮他看清哪种网文类型承载这种体验
4. 检查前三章是否有足够强的类型信号
5. 建议调整书名、简介、标签，并在第一章强化类型标记

### 示例 2：类型混搭冲突

**作者：** "我写的是系统流修仙文，但读者总说体系崩了，我自己也觉得越写越矛盾。"

**你的方法：**
1. 识别可能的状态：G3（类型混搭冲突）
2. 问："系统升级和修仙悟道冲突的时候，你倾向于哪套逻辑？"
3. 帮他找到两套体系的嫁接点——系统是辅助修炼的工具？还是修炼是完成系统任务的手段？
4. 明确主次：一套体系做底层逻辑，另一套做上层表现
5. 建议在前几章就立好规矩：系统和修炼的关系是什么

### 示例 3：副类型喧宾夺主

**作者：** "我写玄幻的，但最近感情线越写越多，男频读者跑了不少。"

**你的方法：**
1. 识别可能的状态：G4（副类型喧宾夺主）
2. 询问比例：感情线占了多少篇幅？每几章出现一次？
3. 询问功能：感情线是在为战斗增加赌注，还是在中断战斗节奏？
4. 建议控制策略：感情线不超过总篇幅20%，且每次出现都要推动主线
5. 考虑这本书是否应该转型为"玄幻言情"面向不同读者群体

## 输出持久化

本技能将主要输出写入文件，以便跨会话保留工作成果。

### 输出路径

分析和诊断结果直接在对话中呈现。如需持久化，**只写到本作品的 `/mnt/user-data/knowledge/genre-audit.md`**，固定文件名。

**写入策略**（详细操作契约见 `## STEP 0：开写前的文件状态检查`）：
- **首次创建**：用 `write_file` 覆盖式写入完整的 4 核心节
- **后续调用**（文件已存在）：用 `str_replace` 在对应节末追加，**禁止用 `write_file`**。追加格式 `### YYYY-MM-DD 追加：<本次主题>`，例如：
  - `### 2026-04-26 追加：仙侠+悬疑混搭策略`（追加到"混搭结构笔记"节末尾）
  - `### 2026-05-03 追加：Ch-15 后必备元素重检`（追加到"必备清单"节末尾）
- **决策依据**：跨会话深度分析（混搭策略、新钩子、节奏建议）属于"作品演进的累积资产"，覆盖会丢上下文；追加保留时间线，作者能看到诊断的演化轨迹

> **不要写**：
> - `/mnt/user-data/chapters/`（章节是 chinese-novelist 的领地，本 skill 只读不写）
> - `/mnt/user-data/knowledge/outline.md`、`characters/`、`entities/`、`concepts/`（wiki-ingest 领地，手写会双源打架）
> - `/mnt/user-data/knowledge/log.md`、`index.md`（同上）

### 主要输出

`genre-audit.md` **至少**含以下 4 节（按此顺序，可视诊断深度增补章节，但下面 4 节一个都不能省）：
- **类型诊断** - 识别出的主类型和副类型，对应 G1~G6 哪个状态（多状态并发要全部列出）
- **必备清单** - 该类型读者期待的核心元素 + 草稿覆盖情况（逐项打勾/缺失）
- **承诺分析** - 前三章承诺了什么爽点、是否兑现
- **混搭结构笔记** - 多类型如何分主次、如何嫁接

> **允许的扩展节**（如有诊断价值才加，否则别灌水）：诊断状态详解 / 干预措施 / 风险预警 / 节奏建议 / 最终结论。
> **不允许**：把上面 4 个核心节合并、省略或改名——下游读者（作者本人 + 后续 skill 调用）依赖固定锚点。

|--------------|----------------------|
| 类型识别结论 | 澄清性问题 |
| 必备元素清单 | 特定章节的讨论 |

## 你不要做的

- 你不替作者写章节或正文
- 你不替他们选择类型——引导他们自己发现核心爽点
- 你不要求类型纯粹——主次分明的混搭是网文常态
- 你不把时代背景与类型混为一谈
- 你不诊断文笔层面的问题（那是 prose-style 技能的领域）
- 你不直接处理角色弧线问题（交接给 character-arc）
- **你不在 `genre-audit.md` 已存在时重写整份报告**——即使你觉得新版本更整洁、结构更优、信息可以重组得更系统。形式覆盖 = 信息丢失，必须走 STEP 0 的 `str_replace` 追加流程。
- **`work_memory` 工具调用受"回合边界 + 授权关键词"双重硬闸约束**：

  **铁律 1：同一回合禁止调用 `work_memory`。**
  完成 `genre-audit.md` 写入的同一轮回复里，**绝对不能**调 `work_memory`——无论你觉得结论多有价值、作者上一条消息授权得多明确。本回合的合法终点只有一种：以问句结尾、等待下一轮用户输入。

  **铁律 2：调用 `work_memory` 的合法前置条件，是"上一条 HumanMessage 含授权关键词"。**
  授权关键词白名单（精确匹配，不做语义推断）：
  - "写进记忆" / "写入记忆" / "记下来" / "记一下"
  - "加约定" / "加进去" / "沉淀" / "存一下"
  - 明确的列表式指令（"把第 1、3 条记进去"）

  **不构成授权**（即使作者语气积极）：
  - "嗯" / "好" / "可以" / "行" / "OK" / "👍"
  - "你看着办" / "你决定" / "随便"
  - 沉默 / 转开话题 / 直接问下一个问题
  - 作者**主动**说"做个 mini 审计"——这是工作请求不是 memory 授权

  **回合 N 的标准收束格式**（写进 `genre-audit.md` 之后必须这样结尾）：
  > 以下 N 条结论建议写进作品记忆，**回复关键词我才会调 `work_memory`**：
  > 1. `[约定]` xxx
  > 2. `[教训]` xxx
  > 3. `[skill候选]` xxx
  >
  > 要写哪几条？回『写进记忆 1,3』或『全写』即可，回『不用』就此打住。

  **回合 N+1 的判定流程**（用户下一条消息抵达后）：
  - 扫描用户消息**全文**，匹配上面的关键词白名单
  - 命中 → 按指定条目调 `work_memory`，**只写作者点名的那几条，不擅自加料**
  - 未命中（包括语义类似但词不在白名单内的回复）→ **不调**，按用户实际意图继续工作

  **理由**：
  - 把"该不该写"的判断从 LLM 的语义推理（不可靠）硬钉到"上一条消息有没有特定字符串"（可机械验证）
  - 把"哪几条值得写"的决策权显式交回作者，skill 只负责候选清单
  - 同一回合禁调，避免出现"我先帮你写了，再问你要不要"这种既成事实模式
  - 反面教材（D 轮翻车实录，2026-04-26）：审计完成后，LLM 在同一回合内自主调 `work_memory` 追加 4-5 条 entry，MEMORY.md 比 audit 文件晚 24 秒被改，作者完全没机会看到候选清单——这正是双重硬闸要根除的

## 关键洞察

网文类型不是写完后挂上去的标签。类型是前三章立下的爽点契约。前三章承诺了一种阅读快感，中间持续兑现和升级这种快感，高潮把这种快感推到极致。每个章节、每个情节点都应该服务于这个契约。

当类型问题出现时，它们通常掩盖了更深层的问题：核心概念不清晰（outline-collaborator）、主角人设与类型不匹配（character-arc）、爽点节奏拖沓（scene-sequencing）、或套路过于老化（cliche-transcendence）。先诊断类型，然后追溯到根本原因。

网文的核心法则：**三章定生死，爽点即正义。** 类型承诺必须快、准、狠。

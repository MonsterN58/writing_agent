# Worldbuilding-Systems：体系化设定设计

## 调用时机

- 用户说"设计修炼体系 / 魔法体系 / 科技树 / 等级体系"
- 用户主动 `/worldbuild` 命令
- `work-setup` 写完 SOUL 后，用户选择"先把世界观搭起来再开写"
- 写到关键体系节点章（境界突破 / 阵法描写 / 法宝鉴定）发现设定缺失

> 本 skill 设计的是**有规则的系统**（修炼/魔法/科技/经济/政治），不是泛泛"世界观"。氛围/历史/地理类世界观属于 `outline-collaborator` 的活儿。

---

## 五种常见体系模板

### 1. 修炼体系（玄幻 / 修真）

**最小要素**：
- 境界划分（5-9 阶最佳，太多冗余）
- 突破条件（资源 / 顿悟 / 雷劫 / 心境）
- 力量倍率（前一阶到后一阶约 5-10 倍战力）
- 副作用（走火入魔 / 寿元 / 体魄反噬）

**模板**（可直接套用让用户填空）：

```
炼气（1-9 层，灵气积累）→
筑基（中期/后期/大圆满，需筑基丹）→
金丹（凝丹时品质决定上限）→
元婴（识海凝形，可元神出窍）→
化神（法则雏形，可短时凌驾天地规则）→
[可选] 大乘 / 渡劫 / 飞升
```

**避免常见坑**：
- 不要每个境界都"小成 / 中成 / 大成 / 圆满"四阶——太冗余，读者麻木
- 不要前期境界太长（超过 30 章还在炼气期 = 节奏崩）
- 突破必须**有代价 + 有不确定性**（保证战斗时的张力）

---

### 2. 魔法体系（西幻）

**最小要素**：
- 魔力来源（先天血脉 / 学习咒语 / 与神/恶魔订契约 / 元素亲和）
- 系统分类（元素系 / 召唤系 / 死灵系 / 时空系等）
- 施法成本（魔力消耗 / 咏唱时间 / 材料 / 精神污染）
- 等级（学徒 → 法师 → 大法师 → 圣域 → 神级）

---

### 3. 科技树（科幻）

**最小要素**：
- 时代标签（蒸汽 / 电气 / 信息 / 太空 / 跨星 / 跨维）
- 关键技术（能源 / 武器 / 信息 / 生命）
- 技术门槛（资源 / 知识 / 政治）
- 副作用（污染 / 失控 / 社会冲击）

---

### 4. 等级 / 阶级（社会体系）

**最小要素**：
- 阶层（贵族 / 平民 / 奴隶 / 异类）
- 流通规则（科举 / 战功 / 血统 / 财富）
- 阶层冲突（主线张力来源）

---

### 5. 经济体系（商战 / 种田）

**最小要素**：
- 货币（黄金 / 灵石 / 灵气币 / 信用点）
- 资源稀缺度
- 交易场所与规则
- 黑市 / 灰色地带

---

## 设计流程

### 立项阶段固定产物

当本 skill 由 setup-pipeline 阶段 ② 触发时，必须写齐以下 6 个文件，不能只写其中一个体系文件：

- `knowledge/world/overview.md`
- `knowledge/world/power-system.md`
- `knowledge/world/factions.md`
- `knowledge/world/geography.md`
- `knowledge/world/history.md`
- `knowledge/world/rules.md`

写完后必须调 `lookup_rebuild`，让后续写章能通过 `lookup_query` 找到这些设定路径。

### 第 1 步：判定是否需要

不是所有题材都需要复杂体系。看 SOUL.md 题材：

| 题材 | 体系密度 |
|---|---|
| 玄幻 / 修真 / 西幻 / 科幻 / 末世 | 必需复杂体系 |
| 武侠 / 仙侠 | 中等（武学 / 内功） |
| 都市 / 言情 / 历史 / 悬疑 / 军事 | 默认简单 / 仅按需补 |
| 游戏 | 必需游戏内规则体系 |

题材属于"默认简单"档时，**本 skill 不主动触发**，只在用户明确要求时介入。

---

### 第 2 步：从 5 W 提问

不要让用户漫无目的设计。按下面 5 W 顺序问：

1. **Why** —— 这个体系**主线作用**是什么？（决定主角成长路径 / 提供升级爽感 / 作为冲突根源）
2. **What** —— 体系最小划分是什么？（5-9 阶最佳）
3. **How** —— 跨阶的方式是什么？（资源 / 顿悟 / 危机 / 成就）
4. **Cost** —— 跨阶的代价是什么？（绝对不能"想升就升"）
5. **Limit** —— 体系顶端是什么？读者能想象到的最高值是？（决定全书战力天花板）

---

### 第 3 步：填表 + 试讲

用结构化表填字段：

```markdown
# 修炼体系：九州大陆

## Why
主角成长主线，前期通过境界差异制造憋点（被高境界压制），中期靠资源/奇遇推进境界。

## 阶位
| 阶 | 名 | 力量倍率 | 关键能力 |
|---|---|---|---|
| 1 | 炼气（1-9 层） | 1× | 简单御物、低级法术 |
| 2 | 筑基 | 5× | 真元外放、御剑短途 |
| 3 | 金丹 | 30× | 元神可离体片刻、御剑千里 |
| 4 | 元婴 | 200× | 元神长时间出窍、寿元 1000 年 |
| 5 | 化神 | 1500× | 触摸法则、镇压一方 |
| 6 | 大乘 | 10000× | 撕裂空间、一念灭一城 |
| 7 | 渡劫 | — | 应对天劫、为飞升做准备 |
| 8 | 飞升 | — | 离开本世界 |

## 跨阶代价
- 炼气→筑基：需筑基丹（青云宗外门年贡 1 颗），失败损伤心脉
- 筑基→金丹：凝丹品级决定一生上限，失败者灰飞烟灭
- 金丹→元婴：需 200 年寿元积累 + 元婴雷劫
- 元婴→化神：千年顿悟，多数卡死在此

## 顶端
化神之上据传有"大乘"，但无人证实。本作前 3 卷主角探索目标是化神。
（埋伏笔：大乘之上是否还有？由 wiki-ingest 标 open）

## 副作用
- 强行突破：走火入魔，识海受损
- 灵根残破者：每阶需 2 倍资源
- 雷劫陨落：丹田尽毁，从此废人

## 主线挂钩
- 第 1 卷：主角炼气 1 层 → 筑基期（章数按 SOUL.md 全书规模分配）
- 第 2 卷：筑基期 → 金丹（章数按 SOUL.md 全书规模分配）
- 第 3 卷：金丹 → 元婴（章数按 SOUL.md 全书规模分配）
```

---

### 第 4 步：试讲一段——验证体系是否能写出场景

让用户**用这个体系想一段战斗描写**：

> "你想象一下：主角筑基中期，对手是金丹初期，主角靠什么扳回？"

如果用户能说出"靠 X 法宝 / Y 阵法 / Z 速度差"——体系够用。
如果用户答不出——体系空洞，需要再加细节。

---

### 第 5 步：双写落盘 —— 草稿 + wiki 锚点

体系一旦与用户讨论确认，**同时落两份**：

**A. 人类可读草稿** → `outline/worldbuilding/<体系名>.md`（完整设计 + 注释 + 待定项）

```
outline/worldbuilding/
├── cultivation-system.md
├── faction-map.md
└── economy.md
```

**B. agent 可检索的 wiki 锚点** → `knowledge/concepts/<slug>.md`（frontmatter 完整 + 简短正文）

对用户明确讨论过的每一个核心概念建 stub，例如修炼 9 阶体系 → 9 个 concepts 文件 + 1 个总纲 concept：

```
knowledge/concepts/
├── cultivation-system.md          # 体系总纲
├── realm-qi-refining.md           # 炼气期
├── realm-foundation.md            # 筑基期
└── ...
```

调 `wiki_ingest` 批量建 stub（type: `concept` 或 `system`），至少包含：

```yaml
---
type: concept
name: 炼气期
aliases: [练气, 炼气境]
category: cultivation-realm
order: 1
summary: 修炼第一阶，吸纳天地灵气入体，共 9 层
foreshadow: []
first_appear_chapter: null
last_update_chapter: null
---

**进阶**：9 层圆满可尝试筑基。
**瓶颈**：5 层是第一道坎（心魔磨炼）。
```

> **为什么双写**：outline 草稿是给你（人类）迭代的，knowledge 锚点是给 agent `wiki_query` / 一致性守门 / 伏笔扫描 / 向量索引用的。立项就建锚点，第一章才查得到。

后续 wiki-ingest 在正文中发现新细节时会 **upsert**（合并 frontmatter + 追加正文），不会覆盖。

## 工具调用约定

| 工具 | 用途 |
|---|---|
| `write_outline` | 写草稿到 `outline/worldbuilding/` |
| `wiki_ingest` | 批量建 wiki 锚点（用 `new_concepts` / `new_locations` 字段） |

**禁止**：
- 不替用户脑补设定（用户没说"飞升后什么样"就留空，标待定）
- 不写用户没讨论过的"额外细节"进 knowledge/（会误导后续写作）

## FAQ

**Q1：用户没要体系但题材是玄幻，主动问吗？**
A：写 SOUL 时如果题材是玄幻/修真/西幻/科幻，主动问一句："修炼体系要现在搭还是边写边定？"用户选边写边定就**等到第一次境界突破章再触发本 skill**。

**Q2：体系太复杂记不住怎么办？**
A：超过 9 阶或字段超过 6 项 = 复杂度超标。本 skill 会自动建议简化。

**Q3：和已有的 `genre-conventions` 区别？**
A：`genre-conventions` 讲**类型惯例**（玄幻该有什么元素、读者期待什么）；本 skill 讲**具体体系机制**（炼气几层、突破怎么算）。前者宏观，后者微观。

**Q4：体系定完后还能改吗？**
A：能，调 `revision` L4。但前 5 章定下的体系，30 章后再改 = 灾难。建议体系字段在前 5 章必须冻结。

**Q5：用户写穿越文，主角带着前世的科技体系怎么办？**
A：等于做两个体系（穿越前科技 + 穿越后修炼），分别写到 `outline/worldbuilding/`。两套体系交集的地方（科技 vs 修炼孰强孰弱）必须额外写一份"交互规则"。


# Continuity-Guard：一致性守门

## 调用时机

- **章节正文写完后自动链**（在 `wiki-ingest` 之后触发）
- 用户主动 `/check <章号>` 命令
- 用户报"X 这里好像和前面矛盾了"
- 切换作品后第一次写新章前的全局体检（可选）

> **本 skill 是写后 QA**，不是文学性分析（那是 `story-analysis` 的事）。本 skill 只查**硬一致性 bug**。

---

## 核心任务

扫五类崩坏：

1. **人设漂移** — 性格 / 修为 / 关系 与 wiki 记录不符
2. **设定矛盾** — 本章设定违反已有规则（如修炼境界顺序错乱）
3. **时间线冲突** — 事件先后顺序与 timeline.md 矛盾
4. **POV 穿帮** — 主角不在场的事却进入主角视角
5. **道具凭空** — 某物未交代获得就出现 / 已失去却又使用

报告写入 `reviews/consistency/章N-YYYY-MM-DD.md`，**不直接改正文**——只报告，让用户决定改不改。

---

## 流程

### 第 1 步：拉取本章 + 比对集

并行：

- 读 `chapters/第N章-*.md` 全文
- `wiki-ingest` 刚抽出的本章实体清单（结构化 JSON）
- 读相关实体的 frontmatter（`grep -l` 命中后 `read_file`）
- 读 `knowledge/log.md` 末尾 5 章摘要
- 读 `knowledge/timeline.md`

### 第 2 步：五类扫描

#### 2.1 人设漂移

对每个本章出场的实体（slug）：

| 字段 | 比对方法 |
|---|---|
| `status`（修为/状态） | wiki 上是"炼气五层"，本章是否冒出"金丹期"而无突破场景 |
| `faction` | wiki 是"青云宗"，本章是否突然写"魔教弟子" |
| 性格 | wiki 是"沉稳寡言"，本章是否突然话痨 + 中二 |
| `aliases` | 本章用的别名是否在 aliases 列表里 |
| 关系 | 本章互动关系是否与 `key_relations` 矛盾 |

#### 2.2 设定矛盾

对本章涉及的概念（concepts）：

- 修炼体系：境界递进顺序 / 突破条件
- 力量规则：金手指限制是否被打破
- 世界规则：时空 / 物理 / 社会规则

#### 2.3 时间线冲突

```
grep -E "^\| <章号>" knowledge/timeline.md
```

检查：
- 本章发生在第几天 / 距上章多久
- 是否和已知事件的时间标签冲突
- 季节 / 节日 / 月相是否合理

#### 2.4 POV 穿帮

- 默认人称（看 SOUL.md）：第三人称限知 / 第一人称
- 本章是否出现"主角不在场却写出别人内心活动"
- 是否突然全知（描写远处某人的想法但主角没旁观）

#### 2.5 道具凭空

- 本章主角使用的道具，是否在前文获得记录里
- 本章丢失/损毁的道具，下章是否还在用（这条要写到 progress/state.json 等下章扫）

---

### 第 3 步：分级报告

按严重度分三档：

| 等级 | 标志 | 处理建议 |
|---|---|---|
| 🔴 **致命** | 修为倒退/世界规则违反/POV 完全穿帮 | 强烈建议改 |
| 🟡 **警告** | 性格小漂移 / 称谓不一致 / 时间线模糊 | 用户裁决 |
| 🟢 **提示** | 用词风格波动 / 不影响主线的小遗漏 | 仅记录 |

---

### 第 4 步：写报告

写入 `reviews/consistency/章N-YYYY-MM-DD.md`：

```markdown
# 第 6 章 一致性扫描

**时间**：2026-05-04 21:30
**扫描章节**：第 6 章 王家窥玉
**总评**：🟡 1 致命 / 1 警告 / 0 提示

---

## 🔴 致命问题

### [人设漂移] 林尘修为表述矛盾

**位置**：本章第 3 场景，约第 1200 字
**正文片段**：
> "林尘运转金丹期真元，一掌劈出……"

**与 wiki 矛盾**：
- `knowledge/entities/lin-chen.md` 记录 `status: 炼气五层`
- 本章前文未写突破场景，无法解释直接到金丹期

**建议修改**：
- 改成"林尘运转炼气真元"，删掉"金丹期"
- 或：在场景 2 加 100 字突破场景作为铺垫（但会改变本章预算）

---

## 🟡 警告

### [设定矛盾] 王家纹章首次出现，未交代规则

**位置**：本章第 1 场景，约第 600 字
**问题**：本章首次提到"王家三爪云纹"，但没交代纹章规则。
**建议**：
- 让 wiki-ingest 把"王家纹章规则"作为新概念沉淀（已自动）
- 或：补一句"那是王家家主直系才能用的三爪云纹"以便读者理解

---

## ✅ 通过项

- 林尘性格（沉稳寡言）：本章对话节制，符合
- 玉佩持有：连续持有，无凭空
- 时间线：本章发生在拜入外门后第 7 天，与 timeline.md 一致
- POV：全章第三人称限知，未穿帮
```

---

### 第 5 步：通知 lead_agent

返回简短结论给前端时间线显示：

> "✅ 章 6 一致性扫描完成：1 致命 / 1 警告 / 0 提示。报告：reviews/consistency/章6-2026-05-04.md"

如果有 🔴，前端时间线显示**红色**并自动展开报告片段。

## 工具调用约定

| 工具 | 用途 |
|---|---|
| `consistency_check` | 后端封装，本 skill 输出报告 JSON 后由后端写入 reviews/ |
| `read_file` | 读章节正文 / wiki / timeline |
| `grep` | 实体匹配 |

**绝对禁止**：
- 不直接改正文（必须用户决定）
- 不修改 wiki 字段（那是 wiki-ingest 的事）
- 不"猜测"用户意图把致命问题降级——发现 🔴 必须报，让用户裁决

## FAQ

**Q1：扫描发现"修为表述不同"，但用户本来就想突破，怎么办？**
A：报 🔴 但在"建议修改"段同时写两条选项：① 删除突破描述 ② 补突破场景。让用户选。本 skill 不替用户决策。

**Q2：扫描太严格，每章都报警告，用户烦怎么办？**
A：用户可在设置里关掉 🟢 提示档，只看 🟡 警告以上。也可以全局关闭本 skill，但**强烈不建议**——一致性 bug 累积到 30 章以后再修就是地狱。

**Q3：和 foreshadow-tracker 重叠吗？**
A：不重叠。本 skill 查"已写出来的内容是否自洽"；foreshadow-tracker 查"埋下的伏笔是否回收"。两者各扫各的。

**Q4：扫不到 wiki（knowledge 还空）怎么办？**
A：第 1-2 章 wiki 还没沉淀，本 skill 跳过比对，只跑"本章内部一致性"（同一段前后矛盾、同一人物同章性格漂移）。从第 3 章起完整跑。

**Q5：用户说"我故意写得矛盾，是反转伏笔"怎么办？**
A：本 skill 不知道用户意图。把矛盾标 🔴 报出来，用户在 `progress/todo.md` 写"已知伏笔，本章故意矛盾"即可。下次扫描时本 skill 读到 todo 里的"已知矛盾清单"会跳过这条。

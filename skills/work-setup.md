# Work-Setup：作品立项与宪章生成

## 调用时机

- 用户首次新建作品（`novels/<作品名>/SOUL.md` 不存在）
- 用户说"我想写本小说 / 我有个灵感"且当前无激活作品
- 用户主动调 `/work-setup` 命令
- 用户改了核心设定（题材/主角换了），需要重写 SOUL

> **不要在 SOUL.md 已存在且未失效时重复触发**——这是入口 skill，不是日常 skill。

---

## 核心任务

通过 5 个最小必要问题，把用户脑子里的灵感**转译成结构化的 `SOUL.md`**，作为后续所有创作的红线约束。SOUL.md 由 lead_agent 在每轮启动时静态注入 system prompt，是作品的"宪法"。

---

## 流程

### 第〇阶段：3 选 1 入口分支（**首步必做**）

立项启动时，先**问用户偏好哪种入口**（调 `ask_user`）：

```
ask_user({
  question: "想从哪种方式开始这本书？",
  options: [
    "A. 引导我从灵感一步步搭设定（推荐新手）",
    "B. 我有完整设定集要导入（已有设定笔记/世界观文档）",
    "C. 不要管设定，我直接开写（不建议，可能崩节奏）"
  ],
  context: "三种方式落盘的资产相同，区别是节奏：A 我们对话引导，B 你贴大段文本我解析分流，C 跳过 setup 直奔写章"
})
```

**根据用户选择路由：**

| 选 | 路由 | 后续 skill |
|---|---|---|
| A | 进入下面的「第一/二/三阶段」逐步对话 | 当前 work-setup 自身 |
| B | 让用户在下条消息里贴/上传完整设定文本 → 路由到 **bulk-import** skill | bulk-import |
| C | 调 `setup_work` 写一份**最简 SOUL**（仅题材+主角一句话），警告"建议至少 5 章后回头补设定" | 跳过 setup，进入 chinese-novelist |

如果用户没明确选 A/B/C 而是直接开始描述故事（"我想写个修仙的废材主角"），按 **A 路由**继续，但内部把这次"自我描述"当作灵感种子。

如果用户上来就贴 >800 字符的长文本，按 **B 路由**直接走 bulk-import。

---

### 第一阶段：捕捉灵感（自由对话）

仅 A 路由用本阶段。

用户进来时通常只有一句话灵感（例："我想写一个修仙小说，主角是个废材"）。

**先复述 + 追问最关键的 1 个空白**，不要一上来就问 5 连问。

例：
> 用户："我想写一个废材逆袭的修仙文。"
>
> 你："好，废材修仙听上去很经典。我想先问你一个最关键的：**主角是被动逆袭（被人欺压到忍无可忍）还是主动逆袭（主动追求强大）**？这会决定全书的爽感节奏。"

---

### 第二阶段：5 问收集核心字段（自然对话，不连环）

按下表顺序问，**每次只问 1 个**，等用户答完再问下一个。已能从前文推断的字段直接跳过。

| # | 字段 | 问法（举例） | 默认推断兜底 |
|---|---|---|---|
| 1 | **题材** | "想写哪种类型？修仙 / 都市 / 言情 / 悬疑 / 科幻 / 历史 / 武侠 / 末世 / 游戏 …" | 用户已说则跳过 |
| 2 | **主角设定** | "主角是男是女？多大？现在处于什么处境？" | 必问，不推断 |
| 3 | **主角动机** | "主角最想要什么？复仇 / 变强 / 守护谁 / 查清真相 / 追求爱情 …" | 由题材+处境推断兜底 |
| 4 | **世界观一句话** | "故事发生在什么世界？有什么核心规则（修炼体系/魔法/科技/超能力）？" | 都市言情可"现实世界"带过 |
| 5 | **红线（不能写什么）** | "有什么是绝对不能出现的？比如：主角不能黑化 / 不写虐主 / 不要后宫 / 必须 HE …" | 用户没说就只列默认 3 条（见下） |

**默认红线**（用户未指定时自动写入）：
- 主角不洗白纯反派行为
- 不出现违反公序良俗的内容
- 重要承诺（伏笔/誓言）必须回收

---

### 第三阶段：推断隐含字段（亮给用户兜底）

下面 3 个字段**默认推断、不主动问**，但要在最终确认时**显式亮出**让用户兜底：

| 字段 | 推断逻辑 |
|---|---|
| **核心冲突** | 玄幻/修真→成长突破；都市→权力/逆袭；言情→爱情阻碍；悬疑→查明真相；末世→生存；其他→看主角动机 |
| **基调** | 用户语气热血→热血爽文；用户提"治愈/温暖"→温馨向；用户提"压抑/黑暗"→暗黑向；默认→轻松爽文 |
| **推荐字数/章** | 长线题材（修真/玄幻/系统流）→ 2500-3500；情感/悬疑→ 2000-3000；微小说→用户明示才用 |

---

### 第四阶段：确认 + 落盘

把上述字段**用一段自然语言复述**给用户，亮出推断假设，等用户认可或修正：

> 例："好，我整理一下：
>
> - 题材：东方玄幻修真
> - 主角：男，18 岁，灵根残废被家族放逐
> - 动机：找回身世真相 + 证明自己
> - 世界观：九州大陆，修炼分炼气/筑基/金丹/元婴/化神五境
> - 红线：不黑化、不虐主、必须 HE、不要后宫
> - 核心冲突我会聚焦在「成长突破 + 真相揭露双线」
> - 基调按「热血爽文 + 偶尔暗线悬疑」走
> - 字数按每章 2800 字左右铺
>
> 哪里不对说一声，否则我落盘开第 1 章。"

用户认可（或修正后再认可）后，**调 `setup_work` 工具**写入 `novels/<作品名>/SOUL.md`：

```markdown
# <作品名>

## 题材
东方玄幻修真

## 主角
- 姓名：（用户给定 / 让 naming skill 起）
- 性别：男
- 年龄：18
- 起点处境：灵根残废被家族放逐
- 核心动机：找回身世真相 + 证明自己

## 世界观
九州大陆，修炼分炼气/筑基/金丹/元婴/化神五境。
（其他规则细节由 worldbuilding-systems skill 后续填充到 knowledge/concepts/）

## 核心冲突
成长突破 + 真相揭露双线

## 基调
热血爽文 + 偶尔暗线悬疑

## 红线（绝对不能写）
- 主角不黑化
- 不虐主
- 必须 HE
- 不写后宫

## 全书规模（**必填**，下游卷纲/细纲必须读这一段）
- 计划总字数：300 万字
- 计划总章数：1000 章
- 计划卷数：6 卷（平均 ≈ 167 章/卷）
- 节奏档：100-300 万字（参 outline-collaborator 字数分档表）

## 写作偏好
- 推荐字数：每章 2800 字左右
- 视角：第三人称限知（默认）

## 一句话核心
一个废灵根少年通过查身世之谜逆袭九州的故事。
```

> ⚠️ **「全书规模」三个字段（总字数/总章数/卷数）禁止留空**。如果用户没说，先 `ask_user` 问"计划写多少字 / 多少章 / 几卷"，问清了再调 `setup_work`。卷纲/arc 细纲都要从这里读章数预算，缺了它们 agent 会按默认 50 章排卷，导致节奏全崩。

---

### 第五阶段：移交给 setup-pipeline 完成全链

SOUL.md 写完后，**不要直接开始写第 1 章**。**默认**按 `setup-pipeline` 的七阶段往下走：

> "作品宪章立好了。下一步我建议按这个顺序把设定补全，再开写：
>
> 1. ✅ SOUL（刚写完）
> 2. 世界观包（修炼体系 / 势力 / 地理 / 历史）← 下一步
> 3. 主要人物（主角 / 核心配角 / 反派，带伏笔）
> 4. 总纲（三幕 / 卷划分 / 主弧）
> 5. 第 1 卷卷纲
> 6. 第 1-5 章细纲
> 7. 第 1 章正文
>
> 这样能最大程度避免后面崩节奏。继续下一步（搭世界观）？还是你想跳过设定直接开写？"

- 用户说"继续/按流程/都搭完" → 移交 `setup-pipeline` 进阶段 ②
- 用户说"直接写第 1 章" → 明确提醒"这会让后面越写越难一致"，再问一次确认，用户坚持则移交 `chinese-novelist`
- 用户说"我想先聊聊剧情" → 移交 `story-collaborator`

## FAQ

**Q1：用户灵感很模糊（"我想写本爽文"），怎么办？**
A：先用类型清单引导他选大方向（修仙/都市/言情…），再按 5 问推进。不要让他先想清楚再来——大多数用户就是边聊边想清楚的。

**Q2：用户想边写边定设定，不想一开始就定红线，怎么办？**
A：红线字段允许留空，写"待定"。但题材+主角+动机+世界观一句话**必须有**——这 4 项缺任意一个都没法写第 1 章。

**Q3：作品已经写了几章，用户想改 SOUL，怎么办？**
A：本 skill 不直接改老 SOUL。提示用户："改 SOUL 会影响后续基调，但已写章节不会自动重写。要继续吗？" 用户确认后调 `setup_work` 覆盖，并在 `memory/decisions.md` 记一笔变更原因。

**Q4：能不能跳过 SOUL.md 直接写？**
A：不能。`chinese-novelist` 写前第 1 步就是读 SOUL.md。缺 SOUL = 缺红线 = 基调飘 = 后期返工。

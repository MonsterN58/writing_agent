
# 结局：诊断技能

你负责诊断小说中结局层面的问题。你的角色是找出结局失败的原因，并引导作者写出既感觉不可避免又令人惊喜的结局。

## 核心原则

**最好的结局既让人感觉不可避免（"当然只能这样结束"），又让人感到惊喜（"我没想到会这样"）。**

这个看似矛盾的要求通过以下方式实现：在故事中埋下种子，让结局从人物和主题中自然生长，在满足更深层期待的同时颠覆表层预期。

只有不可避免性的结局感觉平淡可预测。只有惊喜感的结局感觉随意武断。两者兼具才能带来满足感。

***

## 结局的结构解剖

### 高潮

戏剧张力达到最高点、核心戏剧问题得到回答的时刻。

**高潮必须：**

* 回答核心戏剧问题

* 迫使主角做出最终选择

* 源自故事逻辑，而非外部干预

* 要求角色运用所学到的东西/所成为的自己

### 下降动作

高潮之后的减压阶段。事件趋于平息，后果显现，角色进行内心消化。

**下降动作应该：**

* 展示即时后果

* 开始揭示深层影响

* 让读者喘息

* 向最终解决过渡

### 收束/解决

最终状态——一切的落脚点。

**解决阶段应该：**

* 为主线情节提供闭合感

* 处理主要支线（不必全部解决）

* 展示新的常态

* 以一个余韵悠长的画面或时刻结束

***

## 结局状态

### 状态 E1：随意的结局

**症状：** 解决方式与前文没有逻辑关联。结局感觉随机或断裂。读者的反应是"这从哪冒出来的？"缺乏前期铺垫。

**关键问题：**

* 结局是否源自已建立的人物和情节？

* 这个结局的种子是否在更早的时候就已经埋下？

* 这是否是*这个特定故事*需要的结局？

* 读者重读时能否看到伏笔？

**诊断清单：**

* [ ] 结局只使用已确立的元素

* [ ] 角色在高潮处的选择源自其弧线

* [ ] 结局符合故事的内在逻辑

* [ ] 重读时伏笔应当清晰可见

**干预措施：**

* 找出故事实际构建指向的结局

* 为预期的结局更早地埋下种子

* 确保高潮源自角色成长，而非情节便利

* 使用 setup-payoff 工具追踪已做出的承诺

**依赖排序：** E1 是结局问题的"上游"——常引发 E3（无种子的胜利只能靠外力）和 E4（没盘清承诺导致结尾扩散）。若同时确诊 E3 或 E4，**先解 E1**：先用 setup-payoff 工具盘清承诺清单，再谈胜利归属和收束方式

***

### 状态 E2：可预测的结局

**症状：** 读者从很远处就能看到结局。毫无惊喜可言。过于忠实地遵循类型惯例。表面预期被完全满足。

**关键问题：**

* 是否有任何惊喜元素？

* 是否过于紧密地遵循了类型预期？

* 表面预测是否对应更深层的惊喜？

* 即使"结果"在预期之中，"过程"是否令人惊喜？

**诊断清单：**

* [ ] 至少有一个元素颠覆了预期

* [ ] 通往结局的道路包含惊喜

* [ ] 类型承诺以意想不到的方式实现

* [ ] 情感目的地通过意想不到的路线抵达

**干预措施：**

* 在满足"结果"的同时颠覆"过程"

* 通过出人意料的方式满足情感期待

* 增加不改变目的地但改变旅程的复杂性

* 考虑哪个类型元素可以被反转

**依赖排序：** E2 若伴随"主角行为/反派/桥段全是套路"，**先转 cliche-transcendence**（套路根治后再回头看是否还有 E2 残余）；若主要是"读者准确预测了结局走向"，留在 E2 处理

***

### 状态 E3：未赢得的结局

**症状：** 天降神兵。外部力量解决了主角的问题。结局不需要主角的成长。巧合或运气拯救了一切。

**关键问题：**

* 是主角促成了问题的解决吗？

* 高潮所需的工具/成长是否在早前已确立？

* 是否由外部力量解决了内部问题？

* 角色的转变对结果是否重要？

**诊断清单：**

* [ ] 主角的选择驱动了解决方案

* [ ] 高潮中使用的技能/成长已展示其发展过程

* [ ] 没有新的力量或盟友凭空出现来拯救一切

* [ ] 角色弧线的完成是胜利的必要条件

**干预措施：**

* 移除外部解决方案；迫使主角自己解决

* 提前确立角色在高潮中所需的一切

* 让角色的转变成为解决问题的关键

* 如果有援助到来，确保是主角促成的

**依赖排序：** E3 常与两类问题共发——
* 同时确诊 E1：**先解 E1**（无种子的胜利只能靠外力，不盘承诺改不掉天降神兵）
* 同时存在弧线问题（character-arc 的 A1/A4/A5 等）：**先转 character-arc**——结局未赢得的本质是弧线没收完，弧线一收 E3 自愈

***

### 状态 E4：扩散的结局

**症状：** 结局提出的问题比回答的更多。在解决阶段引入新谜团。本该收束时范围却在扩大。读者感到困惑而非满足。

**关键问题：**

* 主要戏剧问题是否被清晰回答？

* 是否在太晚的时候引入了新谜团？

* 范围是否在解决阶段扩大了？

* 结局是向清晰收束，还是爆发出新的复杂性？

**诊断清单：**

* [ ] 核心戏剧问题已明确回答

* [ ] 最后一幕没有提出重大新问题

* [ ] 范围向解决方向收窄

* [ ] 悬而未决的线索是有意为之，而非无意遗漏

**干预措施：**

* 结局要收束，不要扩散

* 专注于解决已做出的承诺

* 将新问题移至更早的位置（或删除）

* 区分"开放式结局"（有意的模糊）和"未完成"（无意的遗漏）

**依赖排序：** E4 常由 E1 引发——若同时确诊 E1，**先解 E1**。先盘清承诺清单，才能判断结尾出现的"新问题"是承诺延伸（保留）还是无意遗漏（删除）。网文场景注意：续坑勾子是有意 E4，不是问题（见 §网文结局变体）

***

### 状态 E5：过度解释的结局

**症状：** 角色总结主题。冗长的尾声解释每个人的命运。所有线索都收得过于整齐。没有留给读者去感受或解读的空间。

**关键问题：**

* 角色是否在陈述故事的意义？

* 是否有不必要的尾声？

* 所有线索是否收得过于齐整？

* 是否有留白？

**诊断清单：**

* [ ] 没有角色发表解释主题的演讲

* [ ] 尾声（如果有）简短且有余韵

* [ ] 部分线索保持开放或隐含

* [ ] 最后的场景是行动/画面，而非解释

**干预措施：**

* 信任读者的解读能力

* 删掉主题演讲；通过行动来展示

* 以画面结束，而非总结

* 让一些问题留给读者去思考

**依赖排序：** E5 常与 E6 共发（既冗长又说教）——若同时确诊 E6，**先调 E6**：节奏没稳之前删演讲只是加剧仓促感，先把篇幅比例理顺，再砍说教内容

***

### 状态 E6：节奏失调

**症状：** 高潮有效但余波失败。结局感觉仓促（太快）或无穷无尽（太慢）。情感冲击因时机把控不当而流失。读者在最后几页感到不耐烦或困惑。

**关键问题：**

* 下降动作是过长还是过短？

* 解决阶段是否通过行动展示了角色的新状态？

* 最终画面是否有共鸣？

* 收束是否与故事长度成比例？

**节奏指标：**

| 问题       | 症状          | 修复方法           |
| -------- | ----------- | -------------- |
| **仓促**   | 高潮 → 立即结束   | 增加下降动作；让影响得以显现 |
| **冗长**   | 张力释放后仍有大量篇幅 | 削减至核心要素；以余韵结束  |
| **虎头蛇尾** | 解决不及铺垫的力度   | 确保高潮匹配已确立的利害关系 |

**干预措施：**

* 仓促：允许下降动作；让读者消化

* 冗长：在核心解决之后尽快结束

* 最佳平衡点：收束比铺垫更短，与故事长度成比例（**网文按字数分档，见 §网文结局变体的节奏分档**）

**依赖排序：** 若节奏问题不只是结局期、而是延伸到全书（中段也仓促/冗长），**转 scene-sequencing**——那是场景级节奏的归口；本 skill 只管结局期的下降动作和余波控制

## 结局类型参考

| 类型      | 定义           | 最适合         | 风险         |
| ------- | ------------ | ----------- | ---------- |
| **封闭式** | 所有主要问题都得到回答  | 独立小说、类型小说   | 过度解释、过于齐整  |
| **开放式** | 部分问题未得到回答    | 文学小说、系列作品   | 令人沮丧、感觉未完成 |
| **模糊式** | 刻意留下模糊的解读空间  | 不可靠叙述者、哲理小说 | 如果随意则令人不满  |
| **反转式** | 最终揭示重新定义整个故事 | 悬疑、关于认知的故事  | 如果未铺垫则显得廉价 |
| **环形**  | 回到起点，但带有变化   | 强调角色弧线和主题   | 如果强行则显得刻意  |

## 网文结局变体

以下结局类型是中文网文（修真/玄幻/都市/历史/重生/无限流等）领域的高频模式，
每种自带独特的"读者预期结构"。**不要照搬西式 5 类——网文付费读者对结局的容忍度
和期待与传统文学完全不同**。

| 类型           | 定义                              | 最适合                | 核心爽点 / 风险                  |
| ------------ | ------------------------------- | ------------------ | -------------------------- |
| **封神顶点**     | 主角登顶大道/成神/破碎虚空，在最高境界处定格         | 修真、玄幻、洪荒           | 爽点=终极成就感；风险=空洞，缺乏代价        |
| **争霸新秩序**    | 主角推翻旧秩序，建立由自己定义规则的新世界           | 历史改写、重生、都市权谋       | 爽点=改写命运的格局感；风险=权谋线收不拢      |
| **逆袭顶点**     | 当年看不起主角的人逐一面对反差，主角站在顶点俯瞰        | 废材逆袭、扮猪吃虎、退婚流      | 爽点=反差越大越爽；风险=打脸过度、缺尾韵     |
| **归隐田园**     | 高潮后主角主动退场，回到普通生活/隐居山林            | 修真、武侠、长篇玄幻         | 爽点=张弛之美、看破红尘；风险=读者意犹未尽    |
| **续坑勾子**     | 主线收束 + 显式留下下一部 / 番外 / 续集的入口     | 系列网文、IP 化作品        | 商业必要；风险=本部弧线没收完，被骂烂尾断章   |
| **大团圆满级**    | 所有主要角色（含配角/红颜）各得其所、皆大欢喜          | 后宫、种田、温馨日常         | 爽点=情感满足；风险=过度解释（E5）、虚假感   |
| **悲壮殉道**     | 主角以牺牲（肉身/记忆/位格）换取最终胜利           | 悲剧网文、献祭流、救世主弧线     | 爽点=崇高感；风险=未赢得（E3）、突兀     |

**类型选择原则**：
1. 先看作品基调（SOUL.md）——爽文不要悲壮殉道，残酷写实不要大团圆满级
2. 再看主角弧线类型（character-arc 的 work_memory）——废材逆袭天然走"逆袭顶点"，重生复仇可走"封神顶点"或"归隐田园"，平坦弧线适合"争霸新秩序"
3. 最后看篇幅档（见下文节奏分档）——50 万字以下少用"封神顶点"（蓄不够爽），300 万字+ 必须考虑"续坑勾子"防烂尾

### 网文结局节奏分档（按字数）

西方"收束比铺垫短"对网文不成立——付费读者陪了几百万字，结尾草草了事会暴动。
按字数分档参考：

| 全书字数        | 收束篇幅参考       | 备注                                    |
| ----------- | ------------ | ------------------------------------- |
| < 50 万字     | 1-3 万字       | 短篇/中篇网文，西方比例适用，以余韵收束                 |
| 50-100 万字   | 3-8 万字       | 标准长度，需要明显下降动作 + 余波章                  |
| 100-300 万字  | 10-30 万字     | 长篇主流，必须给主要支线/红颜/兄弟/敌人各自的收束章          |
| > 300 万字    | 30 万字+       | 超长篇，常用"封神顶点 + 番外篇"模式，番外篇本身可能 50 万字+ |

**判断标准**：
* 如果读者完结后涌入"太短了""主角对 XX 没交代""太监了"——是收束篇幅不够
* 如果读者涌入"水了几十章""灌水""为了完本而完本"——是收束篇幅过长
* 网文最佳平衡：高潮章后的下降篇幅 ≈ 高潮前最后高潮蓄势篇幅的 1.5-2 倍（vs 西式的 0.3-0.5 倍）

## 角色弧线的完成

结局必须完成角色的转变：

| 弧线类型   | 结局要求             | 检验方法                |
| ------ | ---------------- | ------------------- |
| **正向** | 角色通过行动展示新的真理     | 主角是否通过行为证明了改变？      |
| **负向** | 角色的堕落完成，后果显现     | 悲剧是否从角色的选择中不可避免地产生？ |
| **平坦** | 角色的信念得到验证，世界发生改变 | 坚守是否对结果产生了影响？       |

**关键检验：** 结局处的主角是否通过行动——而非言语——证明了他们已经改变？

***

## 支线情节解决指南

并非每条线索都需要同等程度的闭合：

| 支线类型      | 所需的解决程度      |
| --------- | ------------ |
| **与主线相关** | 必须解决，与高潮相连   |
| **人物塑造类** | 应当解决或展示新状态   |
| **主题映射类** | 如果主题清晰可以保持开放 |
| **世界质感类** | 可以不予解决       |

**原则：** 支线占据的篇幅越多，它需要的解决程度就越高。

## 反模式

### 天降神兵

**模式：** 外部力量解决了主角无法解决的问题。
**问题：** 结局非角色所赢得；角色的旅程毫无意义。
**修复：** 结局必须从已确立的故事元素和主角的选择中产生。

### 续集诱饵

**模式：** 结局主要为了铺设下一部的基础而存在。
**问题：** 这个故事没有获得自身完整的弧线。
**修复：** 每个故事都值得拥有满足感。对下一部的钩子可以与本部的解决并存。

> **与网文"续坑勾子"的区别**：诱饵 = 本部弧线**未自洽**就强留钩子（反模式）；
> 勾子 = 本部弧线**已自洽** + 显式埋下一部入口（网文 E4 变体，系列 IP 商业必要）。
> 判别线只有一条：**本部弧线是否已收完**。收完了再埋钩子是勾子；没收完先埋钩子是诱饵。

### 尾声信息倾泻

**模式：** 冗长地解释之后每个人的命运。
**问题：** 破坏节奏；剥夺读者的想象参与。
**修复：** 以有余韵的时刻结束，而非传记式叙述。信任读者。

### 主题演讲

**模式：** 角色明确说出故事的意义。
**问题：** 说教感；把读者当作无法自行解读的人。
**修复：** 通过行动和画面展示主题，而非通过陈述。

### 完美解决

**模式：** 一切顺利，所有线索收束，没有代价或模糊性。
**问题：** 感觉虚假；消解了旅程的分量。
**修复：** 胜利应有代价。部分线索可以保持开放。

### 虚无主义急转

**模式：** 与故事的情感旅程相矛盾的黑暗结局。
**问题：** 感觉像是为了震惊而震惊，而非赢得的悲剧。
**修复：** 结局必须从故事逻辑中产生，而非作者的突然袭击。

## 类型特定模式

| 类型     | 典型期待             | 颠覆机会           |
| ------ | ---------------- | -------------- |
| **言情** | 有情人终成眷属（HEA/HFN） | 他们如何走到一起；牺牲了什么 |
| **推理** | 真凶揭晓             | 揭晓的影响；侦探自身的改变  |
| **惊悚** | 威胁被消除            | 胜利的代价；失去了什么    |
| **文学** | 主题性解决            | 模糊性；开放的问题      |
| **恐怖** | 怪物被击败或得逞         | 惨胜；腐化持续存在      |
| **奇幻** | 任务完成             | 改变了的英雄回到改变了的世界 |

**原则：** 在宏观层面满足类型期待；在微观层面制造惊喜。

***

## 最终画面

读者被留下的最后印象具有不成比例的重要性。

**有力的最终画面：**

* 与开头呼应（展示变化）

* 以视觉方式体现主题

* 留下情感余味

* 将意义压缩进一个瞬间

**薄弱的最终画面：**

* 总结或解释

* 后续步骤的安排

* 过长的尾声

* 皆大欢喜的群体场面（除非充分铺垫）

***

## 特殊情况

### 系列结局

**系列中的单本：**

* 解决本册的冲突

* 维持更大的系列悬念

* 同时提供满足感和期待感

* 避免纯粹的悬念断点（应有一定程度的解决）

**系列终结：**

* 解决所有主要线索

* 较长的收束可以接受

* 兑现长期铺垫

* 明确完成角色弧线

### 福灾突转

托尔金用来描述突然的、意想不到的转向好结果的术语——灾难看似必然，然后救赎降临。

**要求：**

* 必须有铺垫（契诃夫之枪原则适用）

* 必须是赢得的（角色的成长很重要）

* 必须感觉像恩典，而非运气

* 必须付出代价

## 诊断流程

接到结局相关求助时，按这 6 步走，不要跳步：

1. **倾听+复述**：让作者描述结局的实际感受（"读者觉得仓促/烂尾/突兀…"），用一句话复述确认
2. **匹配状态**：对照 E1-E6 的"症状"列，挑出最像的 1-2 个候选状态（同时存在多个是常态，不要硬选一个）。同时跑两道横向检验——
   * **不可避免性**：能否从前文回溯找到种子？
   * **惊喜性**：是否有元素颠覆了预期？
   两者兼备才是好结局；任一缺失会暴露具体的 E 状态
3. **跑诊断清单**：对每个候选状态，**逐项**问"诊断清单"里的问题，让作者明确回答 yes/no。

   **可选工具：setup_payoff.py**——脚本基于正则共现匹配，对**具体物件类伏笔**（玉佩 / 秘籍 / 钥匙 / 信物等专名）有效；对**意境 / 概念 / 哲学命题类铺垫**（如"灵气不能逼""使劲才能赢"等抽象哲学线）会用"会 / 能 / 知道 / 还在"等高频助词无差别匹配，**90%+ 噪声**。决策树：
   * 关键铺垫是具体物件 / 专名 → 跑工具，结果可用：
     ```bash
     python skills/structure/endings/scripts/setup_payoff.py --analyze <chapter-file-or-dir>
     ```
   * 关键铺垫是哲学 / 心境 / 世界观隐喻（多见中文网文 / 严肃文学）→ **跳过工具**，以人工梳理为主，避免被噪声淹没
4. **确诊+排序**：根据回答确认状态。多状态共存时按依赖排序：
   * E1 + E3 共存先解 E1（无种子谈不上"赢得"，先盘承诺再谈胜利归属）
   * E5 + E6 共存先调 E6（节奏没稳之前，删演讲只是加剧仓促感）
   * E1 + E4 共存先解 E1（先盘清承诺，才能判断哪些"新问题"是承诺延伸、哪些是无意遗漏）
   * E3 + 弧线问题（character-arc 的 A 系列）共发，**先转 character-arc**——结局未赢得本质是弧线没收完
5. **应用干预**：给出对应状态的"干预"方案。**不要替作者决定具体内容**——只给方向和必要节拍，让作者填血肉。结局问题的修复永远是"逆向追踪"：先确定故事实际指向什么结局，再决定写那个结局还是改前文
6. **work_memory 落点（强制执行，不许跳过）**：诊断阶段产出本身就有跨会话价值——LLM 默认偏好继续对话不喜欢落档，必须主动覆盖。**两轮写入**：
   * **诊断结束当下**（即步骤 4-5 完成时）就先写第一轮：已确诊状态（如 E1/E3）+ 已识别硬约束（如"禁某角色救场"）+ 待补种子方向 → `work_memory(action="add", ...)`
   * **方案最终拍板时**（用户明确选了某个路线）再追加第二轮：结局类型选择、承诺清单细化、高潮锚点
   * 写入位置：MEMORY.md 的 `# 约定`（前向约束）/ `# 教训`（已踩坑）两段
   * **禁止借口**："等方案完全成型再写""还在迭代"——只要诊断完成，立即写第一轮；用户明确说"写进 work_memory"则必须当场调用工具，不许只口头答应

> **平台四层记忆机制**：本 skill 的 work_memory 写入会自动通过系统注入的
> `<work_memory>` 块被下游 skill 看到（详见系统注入的 `<four_memory_layers>` 表）。
> 不需要握手协议，不需要主动 read_file。

## 可用工具

### ending\_check.py

分析结局结构和类型。

> **路径提示**: 脚本位于 `skills/structure/endings/scripts/` 目录下。
> 执行时必须使用从项目根目录出发的完整相对路径。

```bash
python skills/structure/endings/scripts/ending_check.py final-chapter.txt
python skills/structure/endings/scripts/ending_check.py --text "一切尘埃落定。叶辰站在山巅之上，俯瞰苍茫大地..."
```

**检查内容：**

* 结局类型检测（封闭式、开放式、反转式等）

* 节奏指标

* 解决 vs. 扩散模式

* 主题陈述性语言

### setup\_payoff.py

跟踪故事中的铺垫和回收。

```bash
python skills/structure/endings/scripts/setup_payoff.py --setup "那把锈蚀的钥匙" --file story.txt
python skills/structure/endings/scripts/setup_payoff.py --analyze story.txt
```

**报告内容：**

* 未回收的铺垫（未发射的契诃夫之枪）

* 缺乏铺垫的回收（天降神兵风险）

* 铺垫到回收的距离

## 交互示例

### 示例 1：随意的结局

**作者：** "Beta 读者说我的结局毫无预兆。"

**你的方法：**

1. 识别状态：E1（随意的结局）
2. 询问："主角在高潮处做了什么？是什么让他们能够这样做？"
3. 检查：那种能力/知识是否在更早的时候已确立？
4. 如果没有：找出需要铺垫的内容
5. 运行 setup-payoff 工具查找缺口
6. **落点**：跟作者敲定要补的铺垫节点后，写入 `work_memory`，下次开新对话续写时这些约定都在：
   ```
   work_memory(action="add", content="""
   # 约定
   - 结局基调：E1 已确诊，禁止"主角突然获得能力"——高潮所用能力必须前文有种子
   - 待补铺垫（来自 setup_payoff.py 的"缺乏铺垫的回收"报告）：
     - 高潮能力 X：第 N 章首次暗示 + 第 M 章实战练手
   """)
   ```

### 示例 2：未赢得的胜利

**作者：** "援军及时赶到了，但感觉很廉价。"

**你的方法：**

1. 识别状态：E3（未赢得的结局）
2. 询问："主角的选择是否促成了援军的到来？"
3. 如果没有：主角必须赢得帮助或自己解决问题
4. 考虑：角色学到了什么，可以成为关键？
5. 建议：移除外部解决方案，或将其与主角早前的行动联系起来
6. **落点**：把"E3 警告 + 高潮锚点改写"写进 `work_memory`，防止再起 subagent 重蹈：
   ```
   work_memory(action="add", content="""
   # 教训
   - E3 已 1 次出现"援军及时赶到"——禁止再用外部力量解决主角无法解决的问题
   # 约定
   - 高潮锚点：主角第 N 章的选择 X 必须直接促成胜利路径（援军只能是放大器，不能是解法）
   """)
   ```

### 示例 3：无尽的收束

**作者：** "高潮之后我不知道怎么结束。我一直在添加场景。"

**你的方法：**

1. 识别状态：E6（节奏失调——冗长）
2. 询问："读者需要看到什么才能感到满足？"
3. 列出必要元素：角色的新状态、核心问题已回答、有余韵的画面
4. 删掉清单之外的一切
5. 以画面结束，而非解释
6. **落点**：把"必看清单 + 删除阈"写入 `work_memory`，下次再加场景前先回看：
   ```
   work_memory(action="add", content="""
   # 约定
   - 收束必看清单（清单外一律删）：
     - 主角新状态（一场戏内呈现）
     - 核心问题已答（角色一句不超过 30 字的回应）
     - 有余韵的最终画面
   # 教训
   - E6 已 1 次出现冗长尾声，再加场景前必须先对照本清单
   """)
   ```

## 输出落点

本 skill 是**诊断 + 引导**型——主要产物是对话里的分析、追问、修复建议。
**不直接写 knowledge/**（那是 wiki-ingest 的独占地盘，跨 skill 写入会破坏 wiki 一致性）。

需要跨会话持久的内容，按三档分流：

### A. 结局诊断决策 → `work_memory` 工具（写 MEMORY.md）

跟作者敲定的"承诺清单 / 高潮设计 / 反复确诊状态"属于**作品级约定**——
下次开新对话、另起 subagent、隔几天回来续写收尾时，这些信息都得在。
用 `work_memory` 工具追加到 MEMORY.md 的 `# 约定` / `# 教训` 段。

**承诺清单的生成路径**：先跑 `python skills/structure/endings/scripts/setup_payoff.py --analyze story.txt`，
把脚本输出转译成 MEMORY.md 条目——
* "未回收的铺垫" 每条 → `# 约定` 的 **承诺清单**（一条铺垫 = 一条对读者的承诺）
* "缺乏铺垫的回收" 每条 → `# 约定` 的 **待补铺垫**（高潮所用元素必须前文有种子）
* 同一类反复确诊 → `# 教训` 的 **状态警告**（如 "E3 已 2 次"）

```
work_memory(action="add", content="""
# 约定
- 结局基调：封闭式 + 福灾突转（必须有铺垫，不许靠运气）
- 承诺清单：
  - 第 3 章那把锈剑：决战必须用上
  - 第 12 章师父遗言："一念之差"：高潮必须呼应
  - 第 28 章敌人的承诺"还会回来"：必须兑现
- 高潮锚点：主角放下剑救废人（呼应 A1 弧线"力量不能定义价值"）
- 最终画面：和开篇同一个镜头但人变了（环形结局）
""")
```

**该写到 MEMORY.md**：

* 结局类型选择（"本作品走环形结局，最终画面呼应开篇"）
* 承诺清单（已埋的契诃夫之枪/角色债/世界规则承诺）
* 福灾突转的铺垫节点（哪一章已埋种子）
* 反复确诊的状态警告（"E3 已 2 次出现『援军及时赶到』，禁止再用"）
* 高潮设计要点（主角必须做哪个违背原信念的选择）

**不要写到 MEMORY.md**：

* 一次性的诊断细节、追问过程、原文引用（留对话即可）
* 角色/世界/组织的设定事实——那是 `knowledge/entities/<slug>.md` 的内容，
  由 wiki-ingest 在章节定稿后自动沉淀
* 跨作品的作者偏好（"用户喜欢留白结局"）——那是全局 memory.json 的层

**5000 字符硬上限**——超额时先 `work_memory(action="remove", content=<旧条目>)`
再 `add`。删旧条目用整段精确匹配。

### B. 实际结局章节 → 不动手

作者写出来的高潮章、收束章、尾声，**通过主流程的 `write_file` 走**
`/mnt/user-data/chapters/第N章-<title>.md`，本 skill **不**直接写章节。
章节定稿后 **wiki-ingest 会自动沉淀**新引入的实体/概念到
`/mnt/user-data/knowledge/entities/<slug>.md`。

要核对"作者写出来的结局"和"原计划的承诺清单"是否还吻合？让 LLM
`read_file /mnt/user-data/chapters/第N章-*.md` 对照 MEMORY.md 里的
承诺清单来诊断；不要试图反向把诊断结论写回 knowledge/。

### C. 长承诺-兑现对照表 / 多版本结局草稿 → workspace

如果一次诊断会话产出了完整的"承诺-兑现矩阵"、多版本结局对照、
逆向追踪的伏笔图谱（>500 字、属于"中间产物"而非"作品级约定"），写到：

```
write_file("/mnt/user-data/workspace/ending-<slug>.md", <内容>)
```

workspace 里东西不进 wiki，作者随时可丢，也不会出现在 `<work_memory>`
注入块里——纯草稿区。

### 对话与文件

| 写到 MEMORY.md（work_memory） | 留在对话中     | 写到 workspace |
| ------------------------- | --------- | ----------- |
| 结局类型选择 + 高潮锚点            | 澄清性追问     | 完整承诺-兑现矩阵   |
| 承诺清单（关键伏笔节点）            | 选项讨论      | 多版本结局对照     |
| 福灾突转铺垫节点                  | 单次诊断追问细节  | 逆向追踪伏笔图谱（长）|
| 反复确诊的状态警告（防重蹈覆辙）          | 作者的结局选择   |             |

## 你不做的事情

* 你不为作者撰写结局

* 你不替他们在结局选项之间做选择（而是引导分析）

* 你不诊断故事中段的问题（交给 scene-sequencing 或 outline-collaborator）

* 你不重写他们的最终章节

你的角色是诊断性的：识别问题，解释为什么是问题，并引导修复方向。写作由作者完成。

## 核心洞见

结局是兑现的承诺。每个故事都通过类型、角色设定和主题方向，对它将呈现的结局做出隐含承诺。好的结局以出人意料的方式兑现这些承诺。

最常见的结局失败是随意的结局：不从已构建的内容中产生的解决方案。修复方法始终如一：逆向追踪。这个故事实际指向什么结局？然后要么写那个结局，要么修改故事使其指向你想要的结局。

结局不能孤立地修复。它是此前一切的顶点。

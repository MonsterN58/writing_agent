# Chapter-Planner：单章纲生成

## 调用时机

- 用户说"写第 N 章 / 接着写 / 下一章"且 `outline/chapters/chapter-N.md` 不存在
- 用户主动 `/outline N` 命令
- `chinese-novelist` 写章流程的**第一步**自动链触发

> **写正文前必须先有单章纲**。直接写正文 = 没规划地走钢丝，崩文概率极高。

---

## 核心任务

把"写第 N 章"这个模糊指令拆解成**可执行的章节蓝图**：

1. 本章目标（推进什么 / 揭露什么 / 完成什么）
2. 出场人物清单（含状态约束）
3. 场景节拍（3-5 个场景，每个 100-300 字摘要）
4. 章末钩子设计
5. 字数预算 + 拍位（爽/憋/打/升）
6. 涉及的设定与伏笔（埋 / 推进 / 回收）

落到 `outline/chapters/chapter-N.md`，**写完后再交棒给 `chinese-novelist` 写正文**。

---

## 流程

### 第 1 步：读取上下文（并行）

同一 LLM turn 并行执行：

- 读 `outline/overall.md`（总纲，定位本章在主线的位置）
- 读 `outline/arcs/`（如有当前弧光）
- 读上一章正文末尾 500 字（拿到上章悬念）
- 调 `wiki-query` 拿相关实体/伏笔
- 读 `progress/state.json` 拿到上次卡点

> SOUL.md 已由 lead_agent 注入，不要 read_file。

---

### 第 1.5 步：机动章判定（重要）

读 arc 细纲后，看当前章号 N 在 arc 里是否被标为 `[机动·待定]`。

**若是机动章**：
1. 从 arc 细纲提取本机动章的 **候选方向 A/B/C** + **共用不变量**
2. 调 `ask_user` 一次性让用户二/三选一：
   ```
   第 N 章在 arc-M 里是软位，目前有 3 个候选方向：
   A. <一句话>
   B. <一句话>
   C. <一句话>
   共用约束：<人物状态 / 必推伏笔 / 字数预算>
   你选哪一个？
   ```
3. 用户选定后，在后续第 2-8 步里把用户选的方向当作"本章目标"展开
4. 立即把选择写入 `progress/arc-decisions.md`，作为后续 `get_chapter_context` 合并 arc context 的权威决议表
5. 单章纲首段必须显式记录："本章从 arc-M 机动位展开，用户选 [A/B/C]，理由：<用户一句话>"

`progress/arc-decisions.md` 追加格式：

```markdown
## 第 N 章 · arc-M 机动位
- **状态**：resolved
- **已敲定**：A|B|C · <一句话方向>
- **共用不变量**：<人物状态 / 必推伏笔 / 字数预算>
- **场景节拍**：<3-5 个节拍压缩成一行>
- **决议理由**：<用户原话或一句话摘要>
- **影响范围**：仅第 N 章，不反向改写 arc 主线
```

如果用户说"先不定"，则状态写 `deferred`，本章纲只做候选范围，不写死剧情选择。

**若非机动章**：跳过本步，直接进第 2 步。

---

### 第 2 步：三级目标链（必填，结构性铁律）

**用途**：防止"章内戏写好但脱离主线"这一最常见的崩文模式。

单章纲首段必须显式列出**四层目标锚点**，缺一行则单章纲视为残缺，`chinese-novelist` 有权拒绝开写：

```markdown
## 目标链
- **本章目标**：<一句话，如"林尘查出王家与父亲的旧怨">
- **服务于 arc**：arc-<M>（第 <SSS>-<EEE> 章）的 <起/承/转/合> 段 —— <引用 arc 纲里原句>
- **服务于卷级**：volume-<V>（<卷名>）的 <起/承/转/合> 段 —— <引用卷纲里原句>
- **服务于总纲**：overall.md 的 <节点名> —— <引用总纲里原句>
```

每一级都必须**引用上游纲的原句**（≤ 30 字即可），不能自创。如果上游纲里找不到对应原句，有两种处理：

1. 当前章号**确实不在任何 arc 覆盖范围** → 暂停，先补 `arc-outline` 再回来
2. 当前章号**在 arc 范围但上游纲描述模糊** → 调 `ask_user` 让用户一句话补齐锚点，然后回写进 arc 纲（让 arc 纲自己先完善）

**机动章降级规则**：

- 对 `[机动·待定]` 章，目标链只强制两级：`本章目标` + `服务于 arc`
- `服务于卷级` 与 `服务于总纲` 降级为"参考锚点"，允许写"不直接推进，但不得冲突"
- 只有当机动章要改变卷级/总纲节点时，才需要升级为四层硬链并让用户确认
- 一个 arc 内机动章 ≥ 2 时，在单章纲"风险"段写预警：本 arc 软位过多，可能稀释主线推进

### 第 2.1 步：节奏定位（辅助信息，不再单独成步）

在目标链之下补一段小定位，用于决定拍位：

- **距离上一个高潮有多远？**（上次爽点/升级/打脸在第几章）
- **距离下一个关键转折有多远？**（下次预期爽点在第几章）

这两问只影响第 3 步拍位选择，不入单章纲正文。

---

### 第 3 步：判定拍位（爽 / 憋 / 打 / 升）

| 拍位 | 特征 | 适用场景 |
|---|---|---|
| **爽** | 主角达成目标 / 打脸成功 / 装逼成功 | 已经憋了 2-3 章后必须给爽点，否则读者跑路 |
| **憋** | 受阻 / 被压制 / 信息揭露但无力反击 | 制造下一个爽点的势能；连续不超过 3 章 |
| **打** | 实战冲突（武力 / 智斗 / 谈判 / 商战） | 阶段性矛盾爆发 |
| **升** | 修为 / 资源 / 关系 / 认知层面的提升 | 长篇必备，每 5-8 章一次 |

> 拍位要**和上一章对照**——避免连憋 / 连爽 / 连打。一般节奏：憋 → 打 → 爽 → 升 → 新一轮憋。

---

### 第 4 步：设计场景节拍（3-5 个）

每章拆 3-5 个场景。每个场景填四要素：

```
【场景 1】茶馆对峙（约 600 字）
- 地点：青云镇·望江楼
- 人物：林尘 vs 王家三公子
- 冲突：王家以族令威胁林尘交出玉佩
- 出口：林尘表面服软，实则记下王家纹章

【场景 2】回客栈思考（约 300 字）
- 地点：客栈·林尘房间
- 人物：林尘、店小二（路人）
- 冲突：内心冲突——是退还是反击
- 出口：决定先查王家底细
...
```

**节拍设计规则**：
- 第 1 个场景必须**承接上章悬念**或**即时冲突起手**（不要"林尘起床洗漱"式开头）
- 中间场景遵循"冲突 → 反应 → 新冲突"的递进
- 最后一个场景必须**埋钩子**（见第 6 步）

---

### 第 5 步：清单本章涉及的设定与伏笔

| 类型 | 项目 | 操作 |
|---|---|---|
| **现有设定** | 修炼境界、青云宗规 | 引用，不改 |
| **新设定** | 王家纹章规则 | 本章首次出现，wiki-ingest 会沉淀 |
| **伏笔回收** | 母亲玉佩为何让王家忌惮 | 推进（不必本章回收） |
| **伏笔新埋** | 王家与林尘父亲的旧怨 | 章末暗示 |

> 引用现有设定时**直接抄 wiki-query 返回的字段**，不要重新编。

---

### 第 6 步：设计章末钩子（只标类型，不写台词）

调 `hook-and-cliffhanger` skill 选 1 种钩子类型 —— **本步只在单章纲里写钩子类型 + 聚焦点**，**不写具体台词**。台词由 `chinese-novelist` 写到章末最后 200 字时，对照 `hook-and-cliffhanger.md` 的「写法要点」现场生成。

钩子类型候选（详细写法见 `hook-and-cliffhanger.md`）：

- **危机钩** — 章末突发新威胁
- **转折钩** — 读者以为 A 揭示 B
- **信息钩** — 抛颠覆性新信息
- **抉择钩** — 推到必须立刻选择
- **悬念钩** — 无法立刻解释的异象
- **倒计时钩** — 明确截止时间
- **反派视角钩** — POV 切换
- **错位钩** — 旧细节意义改变
- **对话钩** — 一句对话戛然而止
- **失败钩** — 主角明确失败

> ⚠️ **重要**：不要把钩子台词写进单章纲。台词被反复抄进 prompt 上下文会污染 LLM 写作样本（出现「瞳孔骤缩 / 脸色一变 / 月光下 + ——」等 AI 套路）。本 step 只决定**钩子类型 + 聚焦事件**，**不预生成台词**。

---

### 第 7 步：字数预算

| 拍位 | 默认字数 |
|---|---|
| 爽（高潮章） | 3000-3500 |
| 打（冲突章） | 2500-3000 |
| 憋（铺垫章） | 2000-2500 |
| 升（升级章） | 2500-3000 |

> SOUL.md 有"推荐字数"字段则覆盖默认值。用户当下指令 > SOUL > 默认。

---

### 第 8 步：落盘单章纲

调 `write_outline` 工具写入 `outline/chapters/chapter-N.md`：

```markdown
# 第 6 章 · 王家窥玉

## 目标链
- **本章目标**：林尘查出王家与父亲的旧怨，被王家家主盯上
- **服务于 arc**：arc-2（第 6-10 章）的"承"段 —— "揭开青云镇地头蛇对主角的敌意根源"
- **服务于卷级**：volume-1（《初入青云》）的"转"段 —— "主角从外门弟子身份迈向卷入势力斗争"
- **服务于总纲**：overall.md 节点 ③ —— "身世之谜首次被外力触发"

## 节奏定位
- 距上次高潮 3 章（外门入门收徒爽点）
- 距下次转折 2 章（拜入内门）

## 拍位
**憋**（中等强度）—— 上章爽完，本章吃瘪为下次反击蓄势

## 出场人物
| 角色 | 状态约束（来自 wiki） |
|---|---|
| 林尘 | 炼气五层，青云宗外门弟子，随身玉佩 |
| 王家三公子 王浩 | 新登场，筑基初期 |
| 玄机子（远程） | 不出场，但林尘内心提到师父教诲 |

## 场景节拍
【场景 1】茶馆对峙（约 600 字）
…
【场景 2】回客栈思考（约 300 字）
…
【场景 3】夜探王家（约 800 字）
…
【场景 4】玉佩异变（约 500 字）
…

## 设定与伏笔
- 现有：修炼境界、青云宗规、王家是青云镇地头蛇
- 新设定：王家纹章规则
- 伏笔推进：母亲玉佩为何让王家忌惮（推进，不回收）
- 伏笔新埋：王家与林尘父亲的旧怨

## 章末钩子
首选：**信息钩**（聚焦：王家家主透露主角身世线索；不写台词，由正文阶段生成）
备选：**抉择钩**（聚焦：林尘是否当夜潜入王家）

## 字数预算
2400 字（憋章）
```

## FAQ

**Q1：用户跳过单章纲直接说"写第 N 章正文"，怎么办？**
A：本 skill 仍然先跑，**但不询问用户**——5 秒内输出单章纲落盘后立即移交 `chinese-novelist` 开写。用户感知就是"好，开始写"，单章纲在后台落盘可供后续追溯。

**Q2：单章纲已经存在，用户又说"写第 N 章"，怎么办？**
A：直接读现有单章纲，跳过本 skill，由 `chinese-novelist` 接管。除非用户明示"重新规划第 N 章"。

**Q3：本章涉及的伏笔回收，但 foreshadow-tracker 显示"还没到回收时机"，怎么办？**
A：尊重用户当下意图，按用户的来，但在单章纲"风险"段写一行提醒："注意：身世之谜伏笔仅埋 2 章就回收，可能过早导致主线张力松弛。"

**Q4：场景拆得太碎或太粗怎么办？**
A：3-5 个最佳。1-2 个 = 节奏太慢；6+ 个 = 章节会膨胀超字数预算。

**Q5：和 outline-collaborator 的分工？**
A：`outline-collaborator` 做**总纲 + 弧光**（跨章规划）；本 skill 做**单章蓝图**。两者读同一份 SOUL.md，不冲突。

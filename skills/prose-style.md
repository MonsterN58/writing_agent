# 散文风格：诊断技能（中文网文专版）

你诊断中文网络小说中**整体散文声音层面**的写作问题。你的角色是识别散文为何未能服务于故事，并引导作者朝着有力、有个性、有画面感的写作前进。

## 触发协议

被 `<available_skills>` 命中后，**先 `read_file /mnt/skills/public/writing-craft/prose-style/SKILL.md` 通读主文件全文**，再决定走 S1-S6 哪条诊断分支、要不要跑 `prose_check.py` / `rhythm.py`。这是平台原生的"先读 SKILL.md 再行动"惯例——别凭描述硬猜流程。

**调用时机判断**：本 skill 是**全局长期声音的体检医生**，不是急诊室。正确切入点：

1. drafting / chinese-novelist 章节**已落地**写盘成 `第N章-章名.md` 后，作者反馈"读起来没画面感 / 风格漂了 / 节奏不对"
2. 上游结构层修订**已完成**（情节、伏笔、节奏的章节级问题已交 scene-sequencing / outline-collaborator 处理过），进入文字层的整体声音诊断
3. 多章已写完后做**风格一致性体检**（"这本书前 5 章和后 5 章像不像同一个人写的"）
4. 作者**主动反馈** S1-S6 的典型词："白开水""华丽过头""读着犯困""句子单调""声音不一""谁在想"

**不要在以下情况调用本 skill**：
- 结构仍有问题（先修结构 → outline-collaborator / scene-sequencing）
- 章节即将被删（不打磨将被删除的内容）
- 角色弧线不完整（先修故事 → character-arc）
- 初稿生成中途（drafting 中途调用 = 过早优化）
- 问题在对白引号内（→ dialogue）
- 问题是局部句式套路 / AI 高频词 / 四字格密度（→ humanizer）

主文件保留诊断主干（5 铁律 + 5 步流程 + S1-S6 速查 + 优先检查规则 + 集成 + 输出落点 + 评分）。下列资料库**按需** `read_file` 加载——别预加载，按诊断分支需要再拉：

- `references/state-library.md` — S1-S6 完整诊断细则（症状/清单/干预/改写示范，第 1-2 步命中具体状态时拉）
- `references/voice-baselines.md` — 声音基准（措辞水平三档 + 中文写作 8 原则 + 朗读测试 + 6 反模式，第 3 步注入声音 / 校 S5 时拉）
- `references/rhythm-and-rhetoric.md` — 节奏与修辞参考表（句长配合、段落节奏、用词陷阱、尾重、比喻规则，S3/S4 改写或第 4 步评分对照时拉）
- `references/polish-checklist.md` — 发章前最终扫描清单（中文网文专属一致性 9 项，作者明确"准备发章 / 最后扫一遍"时拉，不诊断只扫错别字 / 名号 / 时间线 / 设定一致性）

## 核心原则

**散文在起作用时是隐形的。** 读者应该体验故事，而非注意到写作。当散文吸引注意力到自身——无论是平淡、堆砌、还是视角混乱——它就打断了沉浸。

5 条铁律：

1. **服务故事，不炫技** — 散文是船，故事是水。船吸引太多注意力，水就被遮住了
2. **具体压倒抽象** — 用动词和名词驱动，不靠形容词和副词撑场面
3. **节奏匹配内容** — 该快的快，该慢的慢；同一节奏从头到尾就是催眠
4. **声音建立基准** — 全篇有一个可识别的叙述者；偏离基准必须是有意为之
5. **视角忠于一人** — 每个场景一个视角，其他角色只通过外在线索呈现

## 诊断流程

### 第 1 步：通读与状态识别

用 `read_file` 读取目标章节全文。按"作者反馈词"或"通读直觉"对照下方 S1-S6 速查索引，初判命中哪几个状态。

### 第 2 步：脚本量化扫描

如果命中 S3（节奏失控）/ S4（句式单调）/ S1（白开水）—— 跑 `prose_check.py` + `rhythm.py` 拿到量化数据。其他状态（S2/S5/S6）以语义判断为主，工具不替代人眼。

### 第 3 步：朗读测试 + 声音校验

让作者**亲自朗读**有问题的段落。比对作者已建立的基准声音（如有则从 `<work_memory>` 里读）：哪里磕绊？哪里读起来像背课文？措辞水平有没有突变？

如果 S5 / S6 命中且尚未建立基准，按 `voice-baselines.md` 三档表协助作者定档。

### 第 4 步：分层改写示范

按命中状态从严重到轻处理。每处改写必须保留原始叙事信息。**给作者改写示范作为参考**，不替作者重写全篇——本 skill 是诊断性的，最终写作由作者完成。

### 第 5 步：评分与 work_memory 落点（强制执行，不许跳过）

对改写片段打分（见 §质量评分），低于 35 分需重新修订。

诊断阶段产出本身就有跨会话价值——LLM 默认偏好继续对话不喜欢落档，必须主动覆盖。**两轮写入**：

* **诊断结束当下**（第 1-2 步完成、状态命中已确诊时）就先写第一轮：本作品 S1-S6 命中分布 + 严重度排序 + 不出现可跳过的状态 → `work_memory(action="add", ...)` 写 MEMORY.md `# 教训` 段
* **声音基准最终拍板时**（用户明确接受改写方向 / 确认基准档位）追加第二轮：作者声音基准（措辞档位 / 句长偏好 / 视角制式 / 感官密度优先级）→ 写 `# 偏好` 段
* **禁止借口**："等改写完再写""还在迭代""等用户确认风格"——只要第 1-2 步完成立即写第一轮；用户明确说"写进 work_memory"则必须当场调用工具，不许只口头答应

> **平台四层记忆机制**：本 skill 的 work_memory 写入会自动通过系统注入的
> `<work_memory>` 块被下游 skill 看到（详见系统注入的 `<four_memory_layers>` 表）。
> 不需要握手协议、不需要主动 read_file。具体写入实例见底部 §输出落点 A 段。

## S1-S6 状态速查索引

诊断时按本表对照作者反馈词与症状，初步定位。确诊后 `read_file references/state-library.md` 拉详细诊断清单 + 干预措施 + 改写示范。

### 🔴 致命级（读者直接弃文）

- **S1 白开水文（感官缺失）** — 流水账、只有视觉无其他感官、用词泛化（"很大""不错""好看"）
- **S5 声音不一致** — 不同章节像不同作者、措辞水平随机变化、角色串味
- **S6 视角混乱** — 一段话里多人内心活动、全知/限制随意切换、读者分不清"谁在想"

### 🟡 警戒级（读者跳读但未弃）

- **S2 紫色散文（过度修饰）** — 形容词堆叠、比喻过载、景物描写独立成段网文读者必跳过
- **S3 节奏失控** — 打斗拖沓 / 重要场景一笔带过、段落长度全篇雷同

### 🟢 注意级（影响阅读舒适度）

- **S4 句式单调** — 句子全一个长度、连续多句"他/她/我"开头、催眠效果

### 状态共现处理顺序

| 共现 | 顺序理由 |
|------|----------|
| S1 + S2 | 先 S1 补感官，再 S2 删多余修饰 |
| S3 + S4 | 先 S4 句式多样化，再 S3 场景节奏调整 |
| S5 + S6 | 先 S6 定视角制式，再 S5 在视角下建基准声音 |
| 任何 + AI 痕迹 | **立即交接 humanizer**，本 skill 不碰局部句式套路 |

***

## 优先检查规则

按"**扫描成本 × 严重度**"排序，从最便宜最致命的开始处理：

1. **S6-视角混乱**：肉眼可识别（一段两人内心 = 100% 命中），致命级，最优先
2. **S1-感官缺失**：`prose_check.py` 输出"感官过滤词密度"直接看，致命级
3. **S5-声音漂移**：跨章对比叙述者措辞档位，致命级（但需读多章）
4. **S3-节奏失控**：`rhythm.py` 输出句长分布 + 节奏分数，警戒级
5. **S2-过度修饰**：`prose_check.py` 输出"冗余修饰密度"，警戒级
6. **S4-句式单调**：`rhythm.py` 输出"句首多样性分数"，注意级

## 可用工具

> **路径必须**用容器路径 `/mnt/skills/public/writing-craft/prose-style/scripts/`。早期版本写错过 `skills/craft/...` 导致 path not found，**别再写错**。

`prose_check.py` 和 `rhythm.py` 是规则化预扫脚本——眼睛会漏，正则不漏。**通过 sandbox `bash` 调用**。

诊断流程能用追问解决就别上工具——脚本只在"密度量化 + 句长分布 + 多样性评分"这类**量化任务**上比眼睛准。第 1-2 步预扫用工具开局最高效；第 3 步声音校验、第 4 步改写示范、第 5 步评分阶段不依赖工具。

### prose_check.py

扫描中文文风的可正则化问题，输出密度统计。

```bash
# 扫已落地章节
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/prose_check.py /mnt/user-data/chapters/第3章-淬火.md")

# 扫片段文本
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/prose_check.py --text '...'")

# JSON 输出（便于多章对比 / 转译为 work_memory 条目）
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/prose_check.py --json /mnt/user-data/chapters/第3章-淬火.md")
```

**检测覆盖**：
- 感官过滤词密度（"看到""听到""感觉到"等拉远距离的词）
- 冗余修饰检测（多重形容词堆叠）
- 虚词密度（"的地得了着过"等功能词占比）
- 公式化句式（"这是一个…的…""值得注意的是"等）

> **与 humanizer `ai_taste_audit.py` 的边界**：humanizer 扫"AI 痕迹"（P1-P15 句式套路、四字格密度、破折号、章末模板）；本脚本扫"中文散文一般问题"。两个脚本互补不重叠，可同时跑。

### rhythm.py

分析节奏和句式变化模式。

```bash
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/rhythm.py /mnt/user-data/chapters/第3章-淬火.md")
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/rhythm.py --text '他跑了。风很大。巷子很窄。他不敢回头。'")
bash("python /mnt/skills/public/writing-craft/prose-style/scripts/rhythm.py --json /mnt/user-data/chapters/第3章-淬火.md")
```

**报告内容**：
- 句子长度分布（按字符数统计）
- 段落长度变化
- 句首多样性分数（连续同字开头扣分）
- 节奏评分（长短句交错指标）

**何时跳过工具**：
- 章节 < 500 字（密度计算 noise 大）
- 已知章节以**对白为主**（→ 交接 dialogue，本 skill 不碰对白）
- 第 3 步声音校验 / 第 4 步改写示范阶段（语义判断，工具不擅长）

**已知边界（脚本不能替代 LLM 判断）**：

1. **作者风格白名单**：某些症状在某作品是**作者有意为之的风格**而非问题。最常见：抒情古风作品高密度修饰词是其声音特征，扫描会高分但不该改写。脚本不读 work_memory，**LLM 第 1 步必须比对** `<work_memory>` 里 `# 偏好` 段的"作者声音基准档位"——已在白名单的状态跳过改写建议、不入第 5 步评分。

2. **作品级红线**：SOUL.md 可能定义本作品独有的风格红线。**LLM 第 1 步必须 `read_file /mnt/user-data/SOUL.md`**（如果存在）提取作品风格定位，手动校验脚本输出。

3. **跨章节才能识别的状态**：S5（声音不一致）需要多章对比，单章扫描看不出来——必须跨章 read_file 后人工对比。

### 互补（与谁的分工边界——不是重叠是分层）

| 技能 | 关系 |
|------|------|
| humanizer | **分层关键**：本 skill 处理整体风格统一（**全局长期声音**——感官、节奏、声音、视角）；humanizer 处理 AI 痕迹（**局部句式套路**——四字格、破折号、宣传腔、章末模板）。同段文字 humanizer 扫 P1-P15，prose-style 校 S1-S6，互补不重叠 |
| dialogue | 边界：本 skill 在**叙述层**（旁白/心理/场景描写）运作；对白层（引号内的角色声音/潜台词）归 dialogue。识别到对白专属问题立即交接 dialogue |
| cliche-transcendence | 互校：cliche 管套路化情节/角色弧线（结构层）；本 skill 管文字声音（句段层）。同一段"老套描写"——cliche 看是否情节套路，prose-style 看是否声音漂移 |
| story-analysis | 上游：宏观诊断 → prose-style 接句级。本 skill 不做宏观判断，不评估"这章值不值得保留" |
| drafting / chinese-novelist | 上游：drafting 生成初稿，prose-style 是体检医生。**drafting 中途禁止调用本 skill**，避免过早优化误伤创作流 |

### 何时交接

- **交给 humanizer**：当问题是局部句式套路（四字格密度、破折号、否定排比、宣传腔、AI 高频词、章末通用积极结尾）
- **交给 dialogue**：当问题集中在对白（"反派啰嗦""角色都一个调""对白搬运信息"）
- **交给上游 skill**：当问题不是文字层而是逻辑/情节层（"这段不通""节奏失衡是章节级"），提示作者用 scene-sequencing / outline-collaborator 处理章节级结构修订
- **交给 cliche-transcendence**：当问题是结构套路而非声音问题（"主角弧线和别人一样"）
- **交给 character-arc**：当 S5 声音不一致根因是**角色塑造本身飘忽**

### 最小动作约束（防 skill chain 越界）

诊断完成后**只交付诊断结论 + 改写示范**。**不要**自动接力跑下游 skill：
- 不要诊断完 prose-style 自己跑 humanizer
- 不要在 S5 确诊后自动跑 wiki-ingest 写角色档案
- 不要在 S6 确诊后自动改写整章

下游 skill 由用户或 lead agent 显式调用。本 skill 完成 5 步流程 + work_memory 落点 = 任务结束。

## 输出落点

诊断结论和改写决策需要分类落档：作品级约定写 work_memory，章节文本走主流程
`write_file`，长篇对照报告写 workspace。本 skill **不直接** write 到 chapters/ 或
knowledge/——那是 wiki-ingest 的独占地盘。

需要跨会话持久的内容，按三档分流：

### A. 作品声音基准 + S1-S6 命中分布 → `work_memory` 工具（写 MEMORY.md）

跟作者确认的"本作品措辞档位 = 标准档"、"S1/S3 是重灾区"、"限制视角忠于林诚"
属于**作品级约定**——下次开新对话、subagent 续写、几天后回来再润色，
这些档案都还在。用 `work_memory` 工具追加到 MEMORY.md 的
`# 教训`（已踩坑高频状态）/ `# 偏好`（声音基准档）两段。

#### 格式契约（强制 — 防漂移）

每条 MEMORY.md 条目必须满足：

1. **段落归属**：要么进 `# 教训`（已踩坑），要么进 `# 偏好`（基准约定），不进无名段
2. **单条独立成行**：`- 开头`，禁止挤行（已知 dialogue/endings 有过漂移案底）
3. **包含触发场景**：点明"哪种诊断分支 / 哪种作者反馈触发"——同段共享一次诊断时允许统一在末尾独立成行（如 `- 触发：prose-style 跨章诊断 Ch-1 vs Ch-6`），不必每条重复
4. **日期戳记**：当条目反复确诊（≥3 次同一状态）时附 `(确诊 N 次, 截至 YYYY-MM-DD)`
5. **5000 字符硬上限**：超额时先 `work_memory(action="remove", content=<旧条目>)` 再 `add`，删旧条目用整段精确匹配

#### 两轮写入实例

第一轮（第 1-2 步诊断完成时即写）：

```
work_memory(action="add", content="""
# 教训
- 散文状态高频命中：S1-感官缺失（章 1/3/7 各 ≥3 处段落只有视觉）+ S3-节奏失控（打斗章节句长全部 25 字以上一致拖沓）
- 严重度：S1 致命 / S3 警戒，需逐章扫
- 不出现可跳过：S2-过度修饰 / S6-视角混乱，例行扫描节流
""")
```

第二轮（第 5 步评分通过、用户拍板时追加）：

```
work_memory(action="add", content="""
# 偏好
- 叙述者声音基准：标准档（白话主导，偶用古风词为效果）
- 句长档：均长 12 字 + 高方差（动作场景必须降至 8-10 字）
- 视角制式：第三人称限制视角，林诚为主 POV，禁多人内心混段
- 感官密度优先：触觉 > 听觉 > 视觉，避免抽象形容词堆叠
- 已建立白名单：开篇环境描写允许长段抒情（作者风格特征）
""")
```

**该写到 MEMORY.md**：
- 本作品 S1-S6 命中分布（哪几个是重灾区，哪几个不出现）
- 作者声音基准档（措辞 / 句长 / 视角 / 感官）
- 反复确诊的高频状态警告（"S5 已 4 次复现"）
- 改写决策的关键节点（如本作品允许某种风格白名单）

**不要写到 MEMORY.md**：
- 一次性的改写细节、原文 vs 改写并列（留对话即可）
- 角色 / 世界 / 组织设定事实——那是 `knowledge/entities/<slug>.md` 的内容，由 wiki-ingest 沉淀
- 跨作品的作者偏好（"用户喜欢短句"）——那是全局 memory.json 的层

### B. 改写后的章节正文 → 不动手

改写完的章节文本**通过主流程的 `write_file` 走**
`/mnt/user-data/chapters/第N章-<title>.md`，本 skill **不**直接写章节。
章节定稿后 wiki-ingest 会自动沉淀新引入的实体 / 概念到
`/mnt/user-data/knowledge/entities/<slug>.md`。

要核对"已改写章节"和"MEMORY.md 里的声音基准"是否吻合？让 LLM
`read_file /mnt/user-data/chapters/第N章-*.md` 对照 MEMORY.md 诊断；
**不要**反向把改写结论写回 knowledge/（跨 skill 写入会破坏 wiki 一致性）。

### C. 长改写对照报告 / 多章节诊断热力图 → workspace

如果一次会话产出了完整的"改写前 vs 改写后并列"、多章节 S1-S6 命中热力图、
句长分布甘特图、声音基准跨章对照表（>500 字、属"中间产物"而非"作品级约定"），写到：

```
write_file("/mnt/user-data/workspace/prose-style-audit-<slug>.md", <内容>)
```

workspace 里东西不进 wiki，作者随时可丢，也不会出现在 `<work_memory>`
注入块里——纯草稿区。

### 对话与文件

| 写到 MEMORY.md（work_memory） | 留在对话中 | 写到 workspace |
|-------------------------------|------------|----------------|
| 本作品 S1-S6 高频状态分布 | 单次诊断细节 | 改写前 vs 改写后并列 |
| 作者声音基准档（措辞/句长/视角/感官） | 选项讨论 | 多章节 S1-S6 命中热力图 |
| 反复确诊的高频状态警告 | 单次原文引用 | 句长分布甘特图 |
| 风格白名单决策（如允许长段抒情） | 写作者的实验过程 | 声音基准跨章对照表 |

## 质量评分

对改写后的段落进行 1-10 分评估：

| 维度 | 评估标准 | 得分 |
|------|----------|------|
| **画面感** | 读者能"看到"画面而非只"知道"信息？感官密度足够？ | /10 |
| **节奏感** | 句子长度自然变化？段落长短匹配场景节奏？ | /10 |
| **声音一致性** | 措辞水平稳定？没有跨档位漂移？ | /10 |
| **视角忠诚度** | 视角人物清晰？没有内心活动跨人？ | /10 |
| **精炼度** | 形容词副词不冗余？还有废话可删吗？ | /10 |
| **总分** | | **/50** |

**标准：**
- 45-50：可以发布
- 35-44：还需打磨
- < 35：需要重新改写

## 你不要做的

- 你不替作者重写散文（提供改写示范作为参考即可）
- 你不在结构稳固之前进行诊断（交接给 outline-collaborator / scene-sequencing）
- 你不诊断局部 AI 句式痕迹（交给 humanizer）
- 你不诊断对白引号内的问题（交给 dialogue）
- 你不把丰富的散文一概当作"紫色散文"否定——核对是否作者风格白名单
- 你不强迫所有作者去掉所有口语化表达——网文需要口语的亲切感
- 你不机械执行"长短句必须交错"——理解原则，看上下文情绪
- 你不在完成本 skill 后自动接力下游（humanizer / wiki-ingest 等），由用户或 lead agent 显式调用

***

## 关键洞察

散文风格同时在多个层面运作：用词、句子结构、段落流、声音、视角。本 skill 守的是**全局长期声音的统一性**——从第一章到最后一章，叙述者听起来像同一个人；每个场景都有清晰的视角人物；节奏匹配内容情绪；用词具体而非抽象。

humanizer 守的是**局部句式套路的清洁度**——每千字四字格密度、破折号频率、章末模板复用率、AI 高频词。两个 skill 一个望远镜一个显微镜，缺一不可。

目标不是抽象意义上的"好写作"。目标是服务于这个特定故事、这些特定角色、这个特定时刻、这群特定读者的写作。有时简洁，有时丰富，有时口语，有时文学。**始终有意。始终有温度。始终是一个人在讲故事，不是一台机器在拼接。**

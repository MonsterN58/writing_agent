## 核心原则

**去除 AI 味只是一半工作。无菌、没有声音的文字和 AI 生成的一样明显。**

5 条铁律：

1. **删除填充短语** — 去掉开场白和强调性拐杖词
2. **打破公式结构** — 不要二元对比、戏剧性分段、修辞性设置
3. **变化节奏** — 混合句子长度。两项优于三项。段落结尾要多样化
4. **信任读者** — 直接写，跳过软化、辩解和手把手引导
5. **删除金句** — 听起来像名言警句的句子，重写它

## 诊断流程

### 第 1 步：通读与标记

用 `read_file` 读取目标章节，逐段扫描以下 4 大类模式。用 `task` 委派子 Agent 并行检查多个章节。

### 第 2 步：模式识别与改写

按严重程度从高到低处理。每处改写必须保留原始叙事信息。

### 第 3 步：节奏与个性注入

改写后通读全文，确保：

* 句子长度自然变化（不是机械的长-短-长-短）

* 有具体的感官细节而非抽象概括

* 角色的声音有辨识度

* 允许适度的不完美和口语感

### 第 4 步：评分与报告

对改写结果打分（见底部评分表），低于 35 分需重新修订。

### 第 5 步：work_memory 落点（强制执行，不许跳过）

诊断阶段产出本身就有跨会话价值——LLM 默认偏好继续对话不喜欢落档，必须主动覆盖。**两轮写入**：

* **诊断结束当下**（即第 1-2 步完成、模式扫描出结果时）就先写第一轮：本作品 P1-P15 命中分布 + 严重度排序 + 不出现可跳过的模式 → `work_memory(action="add", ...)` 写 MEMORY.md 的 `# 教训` 段
* **改写最终拍板时**（用户明确接受改写结果或确认风格偏好）再追加第二轮：作者风格档（句长偏好 / 破折号容忍度 / 章末是否允许留白 / 感官密度优先级）→ 写 `# 偏好` 段
* **禁止借口**："等改写完再写""还在迭代""等用户确认风格"——只要第 1-2 步完成立即写第一轮；用户明确说"写进 work_memory"则必须当场调用工具，不许只口头答应

> **平台四层记忆机制**：本 skill 的 work_memory 写入会自动通过系统注入的
> `<work_memory>` 块被下游 skill 看到（详见系统注入的 `<four_memory_layers>` 表）。
> 不需要握手协议，不需要主动 read_file。具体写入实例见底部 §输出落点 A 段。

## P1-P15 模式速查索引

诊断时按本表逐项扫，确诊后按需 `read_file /mnt/skills/public/writing-craft/humanizer/references/pattern-library.md` 拉具体模式的症状/改写/要点细则。第 3 步节奏注入与第 4 步评分前对照参考实例时拉 `references/rhythm-injection.md`。

### 🔴 致命级（必须消除）

- **P1 同义词循环** — 一段内称谓反复变换（青年/少年/年轻人/年轻修士轮换）
- **P2 三段式法则** — 描述凑三组（X、Y、Z 顿号三连）
- **P3 否定式排比** — "不仅仅……更是……" / "这不是……而是……"
- **P4 夸大象征意义** — 标志着 / 见证了 / 象征着 / 不可磨灭 / 转折点 / 里程碑
- **P5 破折号滥用** — "——" 制造虚假停顿（每千字 ≤ 1-2 个）
- **P6 宣传式描写** — 旅游宣传册语气（坐落于 / 令人叹为观止 / 充满活力 / 巍峨的）

### 🟡 警戒级（应当修正）

- **P7 高频 AI 词汇** — 此外 / 至关重要 / 深入探讨 / 彰显 / 宝贵的 / 值得注意的是（完整约 95 词扩展词典见 `references/ai-vocab-blacklist.md`，按拐杖/伪深度/宣传腔/陈词滥调/伪学术/陈腐情绪 6 类组织）
- **P8 伴随状语堆叠** — 中文变体：象征着 / 反映着 / 暗示着 多重连用伪造深度
- **P9 系动词回避** — "作为……而存在" / "充当了……媒介" 绕开简单"是/有"
- **P10 虚假范围** — "从 X 到 Y" 但 X 和 Y 不构成有意义尺度
- **P11 通用积极结尾** — 每场景都"光明的未来" / "希望之火"模板

### 🟢 注意级（顺手修正）

- **P12 Markdown 残留** — 正文出现 `**关键词**` / `## 标题` / `- 列表项`
- **P13 填充短语** — "在这个关键的时刻" / "由于……的缘故" / "具有……的能力"
- **P14 过度限定** — "或许可能在某种程度上" 多重限定堆叠
- **P15 表情符号** — 叙述层混入颜文字 / Emoji，全部删除

## 优先检查规则

以下 6 条按"**扫描成本 × 严重度**"排序——P12 最便宜（脚本秒清，绝对确定性）排第 1 位，往下依次是高频致命模式。改写时按此顺序处理：

1. **P12-Markdown 残留**：脚本秒扫，正文必须无 `**粗体**` / `## 标题` / `- 列表项` / `` `代码` ``——零容忍
2. **P2-三段式法则**：描述和形容禁止凑三组，两项或一项更自然
3. **P6-宣传式描写**：场景描写必须包含具体感官细节，禁止旅游宣传册语气
4. **P11-通用积极结尾**：章节/场景结尾禁止无条件乐观，允许留白和不确定
5. **P7-高频 AI 词汇**：禁止使用"此外/至关重要/充满活力/不断演变的格局"等词
6. **P14-过度限定**：删除堆叠的模糊限定词，一个"可能"就够了

## 可用工具

本仓库提供原生工具 `consistency_scan`（启发式自动巡查器，无需 LLM），其 `ai_taste_density` 检测器覆盖 humanizer P5 / P7 / P11 等可正则化模式。

### consistency_scan 工具（推荐）

```
consistency_scan({ projectName: "<作品名>", chapter: 7 })
```

返回 `issues[]` 数组，包含 kind=ai_taste 的命中项：高频 AI 词清单 / "——" 千字密度 / 章末模板命中等。配合**人眼按 P1-P15 速查索引判断**：

- 工具能扫：P5 破折号密度、P7 高频 AI 词、P11 章末通用积极结尾、P12 Markdown 残留、P15 Emoji
- 工具不能替代人眼：P1 同义词循环、P2 三段式、P3 否定式排比、P8 伴随状语堆叠、P9 系动词回避、P10 虚假范围、P14 过度限定（需上下文语义）

### 诊断顺序

1. 调 `consistency_scan` 拿可正则化模式的命中清单
2. 人眼按 P1-P15 速查索引补扫语义类模式
3. 第 3 步节奏注入和第 4 步评分阶段不依赖工具，纯改写

**严重度评级（基于 consistency_scan 输出 + 人眼判断综合）**：

| ai_taste issues 命中数 | 等级    | 处置                          |
| --------------------- | ----- | --------------------------- |
| 0-2  | 🟢 干净  | AI 痕迹轻微，可发布                  |
| 3-5  | 🟡 偏重  | 改写优先级 P5/P7/P11              |
| 6-10 | 🟠 严重  | 多处致命模式，需逐段改写                 |
| 11+  | 🔴 重灾  | AI 味浓，建议整章重写或大幅修订            |

**何时跳过工具**：

- 章节 < 500 字（密度计算 noise 大，单破折号即超阈）
- 已知章节以**对白为主**（本 skill 不诊断对白，扫了也没用）
- 第 3 步节奏注入 / 第 4 步评分阶段（语义判断，工具不擅长）

**已知边界（工具不能替代 LLM 判断）**：

1. **P2 学科/地名/工厂名罗列**：工具会过滤"包括/分别/列着/编号 + 物品后缀"等明显合法罗列，但**学科名（"档案学、目录学、地方史志"）、工厂名（"机器厂、化工厂、纺织厂"）**仍可能命中。LLM 看到 P2 后必须自行判断"是凑三组堆砌、还是合法实体罗列"。

2. **作者风格白名单**：某些 P 在某作品是**作者有意为之的风格**而非 AI 痕迹。最常见：现代悬疑/思维跳跃风格大量用破折号表现内心节奏。工具不读 work_memory，**LLM 第 1 步诊断时必须比对** `<work_memory>` 里 `# 偏好` 段的"作者风格档"——已白名单的 P 跳过改写建议、不入第 4 步评分。

3. **作品级红线词**：SOUL.md 可能定义本作品独有的红线词（如明确禁用"不禁 / 心中暗道 / 目光交汇 / 嘴角微微上扬 / 心头一震"）。**LLM 第 1 步必须 `read_file SOUL.md`** 提取作品红线，手动扫一遍补充工具输出。

### 何时交接

- **交给 prose-style**：当问题不是 AI 痕迹而是作者风格不统一（同一作者前后章风格漂移、第三人称突然跳到第一人称）
- **交给 dialogue**：当问题集中在对白（"反派啰嗦""角色都一个调""对白搬运信息"）——humanizer 不碰引号内的内容
- **交给上游 skill**：当问题不是文字层而是逻辑/情节层（"这段不通""节奏失衡""伏笔没收"），提示作者用 scene-sequencing / outline-collaborator 处理章节级结构修订
- **交给 cliche-transcendence**：当问题是结构套路而非句式套路（"主角弧线和别人一样""反派动机老套"）
- **交给 character-arc**：当 P11（通用积极结尾）反复出现，根因可能是角色弧线本身就是无脑爽文型

## 输出落点

诊断结论和改写决策需要分类落档：作品级约定写 work_memory，章节文本走主流程
`write_file`，长篇对照报告写 workspace。本 skill **不直接** write 到 chapters/ 或
knowledge/——那是 wiki-ingest 的独占地盘（角色 canonical 风格档由 wiki-ingest 在章节
定稿后沉淀到 `/mnt/user-data/knowledge/entities/<slug>.md`）。

需要跨会话持久的内容，按三档分流：

### A. 高频模式分布 + 作者风格偏好 → `work_memory` 工具（写 MEMORY.md）

跟作者确认的"本作品 P2/P6/P11 是重灾区"、"作者偏好长短句对比、禁用破折号"
属于**作品级约定**——下次开新对话、subagent 续写、几天后回来再润色，
这些档案都还在。用 `work_memory` 工具追加到 MEMORY.md 的
`# 教训`（已踩坑高频模式）/ `# 偏好`（作者风格档）两段。

**两轮写入实例**：

第一轮（第 1-2 步诊断完成时即写）：

```
work_memory(action="add", content="""
# 教训
- AI 痕迹高频模式：P2-三段式（章 1/3/7 各 ≥3 处）+ P6-宣传式描写（开场山门描写满屏）+ P11-通用积极结尾（每章末「眼中燃起希望」雷同）
- 严重度：P2 致命 / P6 致命 / P11 致命，需逐章扫
- 不出现可跳过：P1-同义词循环 / P3-否定式排比 / P5-破折号滥用，例行扫描节流
""")
```

第二轮（第 4 步评分通过、用户拍板时追加）：

```
work_memory(action="add", content="""
# 偏好
- 句长档：长短句对比（5字+25字交错），禁机械长-短-长-短
- 破折号容忍度：每千字 ≤ 1 个（本作品基线偏严）
- 章末模式：禁"眼中燃起希望"模板，允许"靠在墙上闭眼"等具身收束
- 感官密度：触觉/痛觉优先，视觉次之，避免抽象形容词堆叠
""")
```

**该写到 MEMORY.md**：

* 本作品 P1-P15 命中分布（哪几个是重灾区，哪几个不出现）
* 作者风格偏好档（句长 / 破折号 / 章末模式 / 感官密度）
* 反复确诊的高频模式警告（"P11 已 4 次复现，禁再用『希望之火』收束"）
* 改写决策的关键节点（如本作品允许章末留白）

**不要写到 MEMORY.md**：

* 一次性的改写细节、原文 vs 改写并列（留对话即可）
* 角色 / 世界 / 组织设定事实——那是 `knowledge/entities/<slug>.md` 的内容，
  由 wiki-ingest 在章节定稿时主动调用沉淀（不是后端流水线，需 LLM 显式 read_file 触发）
* 跨作品的作者偏好（"用户喜欢短句"）——那是全局 memory.json 的层

**5000 字符硬上限**——超额时先 `work_memory(action="remove", content=<旧条目>)`
再 `add`。删旧条目用整段精确匹配。

### B. 改写后的章节正文 → 不动手

改写完的章节文本**通过主流程的 `write_file` 走**
`/mnt/user-data/chapters/第N章-<title>.md`，本 skill **不**直接写章节。
章节定稿后 **由 LLM 主动调用 wiki-ingest skill** 沉淀新引入的实体 / 概念到
`/mnt/user-data/knowledge/entities/<slug>.md`（wiki-ingest 是需显式触发的 skill，
不是后端流水线，humanizer 不替它兜底）。

要核对"已改写章节"和"MEMORY.md 里的高频模式警告"是否吻合？让 LLM
`read_file /mnt/user-data/chapters/第N章-*.md` 对照 MEMORY.md 诊断；
**不要**试图反向把改写结论写回 knowledge/（跨 skill 写入会破坏 wiki 一致性）。

### C. 长改写对照报告 / 多章节模式热力图 → workspace

如果一次会话产出了完整的"改写前 vs 改写后并列"、多章节 P1-P15 命中热力图、
节奏分布甘特图、AI 词频排行榜（>500 字、属于"中间产物"而非"作品级约定"），写到：

```
write_file("/mnt/user-data/workspace/humanizer-audit-<slug>.md", <内容>)
```

workspace 里东西不进 wiki，作者随时可丢，也不会出现在 `<work_memory>`
注入块里——纯草稿区。

### 对话与文件

| 写到 MEMORY.md（work_memory） | 留在对话中     | 写到 workspace      |
| ------------------------- | --------- | ---------------- |
| 本作品 P1-P15 高频模式分布         | 单次诊断细节    | 改写前 vs 改写后并列     |
| 作者风格偏好档（句长/破折号/感官）        | 选项讨论      | 多章节 P1-P15 命中热力图 |
| 反复确诊的高频模式警告（防重蹈覆辙）        | 单次原文引用    | 节奏分布甘特图          |
| 改写决策关键节点（如允许章末留白）         | 写作者的实验过程  | AI 词频排行榜         |

## 质量评分

对改写后的章节进行 1-10 分评估：

| 维度       | 评估标准                  | 得分      |
| -------- | --------------------- | ------- |
| **直接性**  | 叙述是否直截了当？还是充满铺垫和绕圈？   | /10     |
| **节奏感**  | 句子长度是否自然变化？还是机械重复？    | /10     |
| **感官密度** | 是否有具体的感官细节？还是全靠抽象形容词？ | /10     |
| **角色辨识** | 闭上眼能分辨谁在说话吗？          | /10     |
| **精炼度**  | 还有废话可删吗？              | /10     |
| **总分**   | <br />                | **/50** |

**标准：**

* 45-50：可以发布

* 35-44：还需打磨

* < 35：需要重新改写

## 这是什么

墨枢 Agent 是一个面向中文网文创作的本地化写作工作台。

它不是单纯的“聊天框接大模型”，而是把以下几件事串起来：

- 新建作品，逐步完成立项，生成作品宪章 SOUL.md
- 管理世界观、人物、地点、物品、大纲、卷纲、章纲
- 让 Agent 根据上下文写章、改稿、补设定、查前文
- 自动沉淀知识库，减少长篇连载里的设定冲突
- 追踪伏笔、长期记忆、风格偏好、历史版本和运行 trace
- 一键导出整本小说为 Markdown

如果你是 0 基础用户，可以把它理解成：

> 一个会“陪你搭设定、记前文、写章节、查漏洞”的小说创作工作台。

---

## 适合谁

- 想开始写网文，但不想自己手动管理几十个设定文件的人
- 已经在写长篇，想降低人物设定漂移、伏笔遗忘、前后矛盾的人
- 想把写作流程做得更工程化一些的人
- 希望本地保存作品资料，而不是把所有内容都散落在聊天记录里的人

如果你只是想临时问一句“帮我写一段文案”，这个项目会显得偏重。
如果你想认真维护一部长篇，它会更合适。

## 你能用它做什么

| 阶段 | 能力 |
| --- | --- |
| 立项 | 生成 SOUL.md，梳理题材、主角、世界规则、红线与风格基线 |
| 设定 | 管理人物、地点、物品、体系设定、关系、时间线 |
| 规划 | 维护总纲、分卷、弧线、单章章纲 |
| 写作 | 根据当前项目上下文写下一章、改写某段、补强爽点或钩子 |
| 审核 | 章节评分、一致性检查、伏笔预警、trace 回放 |
| 沉淀 | 自动写入 knowledge、memory、style、reviews 等目录 |
| 导出 | 合并全书，输出到 exports/full-novel.md |
| 扩展 | 支持用户自定义技能，把你的写作偏好固化成规则 |

项目内已经内置了 40+ 个技能文件，覆盖立项、角色、设定、大纲、写章、修稿、伏笔、Wiki 维护等常见场景。

## 5 分钟快速开始

### 1. 准备环境

你需要先安装：

- Node.js 18 或更高版本
- Git
- 一个可用的 OpenAI 兼容模型 API Key

支持 OpenAI 兼容接口。也就是说，不一定非得是 OpenAI，只要你的服务支持兼容的 API 格式即可。

### 2. 拉取项目并安装依赖

```bash
git clone <你的仓库地址>
cd writing_agent
npm install
```

### 3. 启动项目

```bash
npm run dev
```

这个命令会同时启动：

- 前端页面： http://localhost:5173
- 后端服务： http://localhost:8787

### 4. 打开网页

在浏览器访问：

http://localhost:5173

### 5. 先配置 LLM

这是最适合新手的方式，不用先手动折腾环境变量。

打开页面后：

1. 点击顶部“更多”
2. 选择“LLM 配置”
3. 填入以下内容

- API Key：你的模型服务密钥
- Base URL：模型服务地址，比如 OpenAI、DeepSeek、Qwen 等兼容接口
- 主模型：日常对话和 Agent 主循环使用的模型

然后点击：

- “测试连通”确认能连上
- “保存配置”写入本机配置文件

配置会保存在 data/llm-config.json，只在你的本机生效。

### 6. 创建第一个作品

你有两种方式：

- 点击顶部作品切换器右侧的“+”
- 按 Ctrl/Cmd + K 打开命令面板，选择“新建作品”

### 7. 开始第一轮对话

新建作品后，直接在聊天框输入自然语言即可，例如：

```text
我想写一本偏黑暗修仙的长篇小说，主角前期弱、后期狠，先帮我立项。
```

或者：

```text
继续把这本书的世界观、主要人物和总纲补齐。
```

等项目基础搭好后，再继续：

```text
给我出第一章章纲。
```

```text
写第一章。
```

## 对 0 基础用户最友好的体验路径

如果你第一次接触这种项目，建议按下面顺序体验：

### 路线 A：先观察示例作品

仓库里已经带了示例项目，放在 novels 目录下，比如：

- 100%不空军系统
- 恐惧值

你可以先启动项目，切换到这些作品，看看它们的目录结构、章节文件、知识库和大纲是怎么组织的。

### 路线 B：再创建你自己的作品

推荐顺序：

1. 先让 Agent 帮你立项
2. 再补人物、世界观、地点、物品
3. 再生成总纲、卷纲、章纲
4. 最后让它开始写正文

这样会比“刚建项目就直接写第一章”稳定很多。

因为这个项目的核心优势，本来就不只是生成文字，而是先搭上下文，再持续写下去。

## 界面说明

### 顶部栏

- 切换作品 / 新建作品
- 查看当前立项阶段
- 打开命令面板
- 打开“更多”菜单：长期记忆、我的技能、章节仪表盘、伏笔预警、LLM 配置、导出全本、删除作品

### 左侧文件树

用于查看当前作品下的文件。

常见目录包括：

- outline：大纲、卷纲、单章纲
- chapters：正式章节
- knowledge：人物、地点、设定、时间线、伏笔等知识库
- reviews：评分、一致性报告、伏笔报告
- memory：长期记忆
- style：风格样本
- exports：导出结果

### 中间聊天区

这是主工作区。

你可以：

- 用自然语言描述你的创作目标
- 实时看到 Agent 的输出过程
- 观察工具调用、任务进度、状态变化

### 右侧/侧边面板

可以按需打开：

- 我的技能：管理自定义写作技能
- 长期记忆：记录硬约束、人物口吻、反复踩坑
- 章节仪表盘：查看章节字数与评分
- 伏笔预警：查看待回收伏笔
- Trace：回放一次完整执行过程

## 项目目录说明

下面是你最需要理解的几个目录。

```text
writing_agent/
├─ src/                  前端 React 界面
├─ server/               后端 Express 服务
├─ skills/               内置技能库（Markdown）
├─ novels/               所有作品数据
├─ evals/                离线评测与回归测试
├─ scripts/              构建辅助脚本
├─ package.json          项目脚本与依赖
└─ README.md
```

### novels

这是最重要的目录。你的作品数据基本都在这里。

每个作品一个单独文件夹，通常会包含：

```text
novels/你的作品名/
├─ SOUL.md
├─ meta.json
├─ outline/
├─ chapters/
├─ knowledge/
├─ reviews/
├─ progress/
├─ memory/
├─ style/
├─ runs/
└─ exports/
```

可以简单理解为：

- SOUL.md：这本书的“作品宪章”
- outline：创作规划层
- chapters：正文层
- knowledge：知识库层
- reviews：诊断层
- runs：运行记录层

### skills

这里放的是系统内置技能。

它们本质上是 Markdown 文件，用来告诉 Agent 在不同写作阶段应该怎么做。比如：

- work-setup：立项
- worldbuilding-systems：体系设定
- character-bible：人物档案
- outline-collaborator：总纲规划
- chapter-planner：单章纲
- chinese-novelist：写正文
- revision：改稿
- wiki-ingest：章后知识沉淀
- foreshadow-tracker：伏笔追踪

这意味着项目的很多能力是“可读、可改、可扩展”的，而不是全都写死在代码里。

### server

后端服务负责：

- 作品和文件管理
- 对话与 SSE 流式输出
- LLM 配置和连通测试
- 章节评分、一致性扫描、伏笔重建
- 长期记忆、用户技能、导出和 trace 管理

### evals

这里是离线评测脚本。

它不会直接帮你写小说，但会帮助开发者检查：

- 技能路由是否正常
- 工具 schema 是否一致
- 评分逻辑是否退化
- 关键服务模块是否还按预期工作

## 配置方式

### 方式 1：推荐，新手直接在界面里配

优点：

- 不用手写环境变量
- 不用重启后端就能生效
- 配置只存在本机，适合个人使用

配置保存在：

```text
data/llm-config.json
```

### 方式 2：用 .env 配置

如果你更习惯环境变量，也可以在项目根目录新建 .env：

```env
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_MODEL_CHEAP=gpt-4o-mini
LLM_MODEL_WRITER=gpt-4o
LLM_MODEL_ULTRA=gpt-4o
LLM_EMBED_MODEL=text-embedding-3-small
LLM_TEMPERATURE=0.8
SERVER_PORT=8787
```

说明：

- 不填界面配置时，系统会回退到 .env
- 如果界面里保存了覆盖项，会优先使用界面配置
- Base URL 需要是 OpenAI 兼容接口

## 为什么这个项目适合长篇创作

很多 AI 写作工具的问题不是“写不出一句话”，而是：

- 写到第 20 章后忘了前面的设定
- 配角口吻越来越不像自己
- 爽点有，但承接和回收越来越乱
- 所有信息都散在聊天记录里，后期根本没法维护

墨枢 Agent 的思路是把这些东西拆开管理：

- 用 SOUL.md 固定作品底层规则
- 用 outline 保持剧情规划
- 用 knowledge 管理可检索的设定事实
- 用 memory 管理长期偏好与硬约束
- 用 reviews 和 foreshadow 做诊断
- 用 runs 保存执行 trace，方便复盘

它更像一个“写长篇的工作台”，而不只是“写一句算一句”的聊天工具。

## 自定义技能和长期记忆

这是项目很值得用起来的两个能力。

### 自定义技能

如果你总会反复强调某类要求，比如：

- 战斗章必须短句、快切、章末留危机
- 感情戏不要说教，要靠动作和停顿推进
- 悬疑文里每章都要留下一个可追问的问题

那你可以把这些规则做成自己的技能。

界面里可以：

- 新建技能
- 上传 Markdown 技能文件
- 根据一句话自动生成技能草稿

### 长期记忆

适合记录那些“每次都不想重新解释一遍”的规则，比如：

- 某角色说话必须冷、短句、少感叹号
- 世界规则中不允许死者复活
- 主角不能轻易暴露底牌

这些内容会参与后续提示词构建，帮助 Agent 少犯老毛病。

## 常见问题

### 1. 页面能打开，但一聊天就报错

通常是没有配置 LLM_API_KEY，或者 Base URL / 模型名填错了。

优先检查：

- “更多” -> “LLM 配置”
- 先点“测试连通”
- 确认模型服务支持 OpenAI 兼容接口

### 2. 第一次写章节很慢

这是正常的。

因为系统可能会同时做这些事情：

- 读当前项目上下文
- 读取或生成章纲
- 查询知识库
- 记录 trace
- 在写完后沉淀 Wiki 或做检查

### 3. 我能不能不用 .env

可以。对普通用户来说，直接用界面里的“LLM 配置”就够了。

### 4. 数据会存在哪里

主要在两个地方：

- novels：你的作品、章节、设定、知识库、导出结果
- data：你的本机 LLM 配置覆盖

### 5. 我能不能把它当成通用聊天机器人

能聊，但这不是它的强项。

它更擅长围绕“某一部小说项目”持续工作。

### 6. 端口被占用了怎么办

默认端口是：

- 前端 5173
- 后端 8787

如果 8787 被占用，可以改 SERVER_PORT。
